# 택일 자료 만들기 (월별 글)

한 달을 계산해 블로그에 올릴 글을 만드는 일이다. 2026-09-18부터 **생성기가 글을 쓴다.** 손으로 원고를 쓰지 않는다.

**점수 · 순위 · TOP N · 0~100 은 내지 않는다**(법전 60조, 메모리 `feedback-no-composite-score`).
라이브 글(`app/taekil-2026-10.html`)도 「점수와 순위는 매기지 않았습니다」라고 적혀 있다. 스킬이 다른 말을 하면 글이 서로 반대 말을 한다.

## 판정이 하는 것

전부 판정엔진(`app/panjeong.js`) + 출산택일 관점(`app/gwanjeom.js`)이 하고, 시뮬레이터(`app/taekilsim.js` 의 `ChaeksaTaekilSim.하루`)가 하루를 시진 창으로 나눠 부른다.
생성기는 새로 재지 않는다 — 그 값을 글로 옮길 뿐이다.

- **궁통보감 = 거르개** — 이 계절에 이 아이에게 필요한 글자가 천간에 있나(조후용신표 120칸, `docs/12`)
- **자평진전 = 거르개** — 무슨 격이고 파격인가. 기계는 「파격인가 아닌가」까지만 말한다
- **적천수 = 참고** — 걸림을 매기지 않는다. 걸리지 않는 곳들이 서로 어떻게 다른지(기세 · 흐름) 읽는 데 쓴다
- **걸리는 것 없음** = 두 거르개 모두 걸림 없음
- **으뜸** = 걸리는 것 없음 + 궁통보감이 적어 둔 글자(먼저 찾는 글자 + 돕는 글자)가 천간에 다 있음(68조)

줄은 날짜순이다. 「순위가 아닙니다」를 글에 적는다(생성기가 넣는다).

## 순서

CLAUDE.md 「월별 글」 줄 그대로다: 개발 서버에서 달을 덤프 → `tools_wolbyeol.py`(종합) · `tools_gungtong.py`(궁통보감) → `tools_jeongbon.py`(정본).

### 3. 달을 덤프한다

`tools_wolbyeol.py` 맨 아래 「덤프」 주석과 같은 코드에 보내는 줄만 붙인 것이다. y · m 만 바꾼다.
월별 글은 원국만 보므로 성별은 'M' 으로 둔다(남아 · 여아가 같다 — 갈리는 것은 대운이고, 대운은 보고서에서 본다). 곳은 서울.

```js
const S=ChaeksaTaekilSim, 요일='일월화수목금토', y=2026, m=10, days=[];
for (let d=1; d<=new Date(y,m,0).getDate(); d++) { const h=S.하루(y,m,d,'M','KR:서울');
  days.push({d, 요일:요일[new Date(y,m-1,d).getDay()], 밀림:h.밀림, rows:h.rows.map(r=>({시진:r.시진, 창:r.창, 시작:r.시작, 일주:r.일주, 시주:r.시주, 월주:r.월주, 연주:r.연주, 밤끝:!!r.밤끝, 없음:!!(r.본&&r.본.없음), 으뜸:!!(r.본&&r.본.으뜸), 눈:r.본.눈들.map(n=>({고전:n.고전, 걸림:!!n.걸림, 모름:!!n.모름, 한줄:n.한줄, 풀이:n.풀이}))}))}); }
const res = await fetch('http://127.0.0.1:8793/m'+y+'-'+m+'.json', {method:'POST', body:JSON.stringify(days)});
({ok: res.ok, 날수: days.length})
```

`하루(y, m, d, 'M'|'F', 'KR:서울')` 가 돌려주는 것: `{ rows, 곳, 밀림 }`. rows 는 그날 시진 창 13개(자시가 새벽 앞 · 밤 끝 두 번),
행마다 `창`(시계 시각) · `시진` · `일주` · `시주` · `밤끝` · `본.걸림수` · `본.없음` · `본.으뜸` · `본.눈들[]`(`key` · `고전` · `걸림` · `모름` · `한줄` · `풀이`).
자세한 것은 `택일상담` 스킬 「하루가 돌려주는 것」.

### 4. 글을 짠다

```
python tools_wolbyeol.py <scratchpad>/month/m2026-10.json 2026 10      → 붙여넣기-10월출산택일.html + app/cards/2026-10/
python tools_gungtong.py <scratchpad>/month/m2026-10.json 2026 10      → 붙여넣기-10월궁통보감.html + app/cards/2026-10-gungtong/
python tools_jeongbon.py                                                → app/taekil-*.html 정본 · 사이트맵 · taekil.html 목록
```

카드 없이 글만 다시 짜려면 `tools_wolbyeol.py … --no-cards`.

**종합 글은 기존 파일을 틀로 쓴다.** `tools_wolbyeol.py` 는 `marketing/붙여넣기-{월}월출산택일.html` 의 머리(스타일 · 복사 단추)와 꼬리(script)를 그대로 두고
`#doc` 본문만 갈아 끼운다. 고정 단락 셋 — 「먼저 — 출산 날짜는 의사가 정합니다」 「이달의 절기」 「부모 사주 하나로 못 쓰는 날이 이만큼 갈립니다」 — 과 해시태그는 **옛 글에서 가져온다.**
그래서:

- 파일이 없는 달이면 다른 달 파일을 복사해 두고 돌린다. 그다음 **절기 단락과 부모 일지 단락을 그달 것으로 손으로 고친다**
  (절기 시각은 그날 `하루` 의 rows 에서 월주가 바뀌는 분을 본다. 부모 일지 단락은 덤프의 일지 · 시지와 부모 일지의 충을 세고, 무엇을 셌는지 글에 한 줄로 밝힌다)
- 파일 이름에 해가 없다(`10월출산택일`). 지금 열두 편은 2026-09 ~ 2027-08 이다. 다음 해 같은 달을 짜면 덮어쓴다 — `tools_jeongbon.py` 의 `MONTHS` 도 같이 본다

**궁통보감 글**은 `tools_gungtong.py` 안의 계절 말 · 원문 옮김 표와 `.taekil/_wonmun_verified.json`(원문과 글자 단위로 대조한 구절)을 쓴다. 원문 구절은 지어내지 않는다.

## 진태양시 — 시계 시각

한국은 동경 135도를 표준시로 쓰는데 그 선은 일본을 지난다. 그래서 **시계 시각과 사주의 시(時)가 다르다.**
경도 보정(서울 −32분)에 균시차가 더해져 **날마다 다르다** — 서울은 시계가 해보다 15~46분 빠르다(10월 16분쯤, 12월 28분쯤).

`하루` 의 `창` 은 엔진에 분 단위로 물어 정한 경계다. **손으로 셈하지 않는다.** 교과서 시진표(미시 = 13:00~14:59)로 적은 글이
독자 댓글로 잡힌 적이 있다 — 그 글대로 13:10 에 낳으면 다른 사주가 된다. `tools_form.py` 가 교과서 시각을 막는다.

병원에는 「미시에」가 아니라 「오후 1시 몇 분 이후로」라고 말하게 한다(생성기가 넣는다).

## 글에 대해 지킬 것

- **의료 면책은 맨 앞이다.** 「출산 날짜는 의사가 정합니다」 단락(생성기가 옛 글에서 가져온다). 이사 · 계약 택일이면 「계약 · 법률 판단이 먼저」로 바꾼다
- **기준을 밝힌다.** 세 고전을 고른 것, 둘로 거르고 하나는 참고로 읽는 것은 저희가 정한 것이라는 단락(생성기가 넣는다)
- **제목은 질문, 첫 줄은 답**(메모리 `feedback-why-first-titles`). 생성기 제목 「왜 {해}년 {월}월 출산택일은 이 시각인가요」, 첫 줄 「답부터 드리면, …」
- **표는 쓰지 않는다.** 네이버 모바일에서 본문이 옆으로 밀린다. 비교는 `<blockquote>` 안 `▸` 줄로
- 네이버가 살리는 태그는 `h2 h3 p b i hr blockquote` 정도다. class · inline style 은 버려진다
- 격 성패 말은 **성격 · 구응 · 기신 있음 · 파격** 넷만
- 상담 내용을 사례로 쓰지 않는다. 「지난 상담」「실제 사례」「의뢰인」 금지 — 만든 예로 쓰고 밝힌다
- 글 꼬리의 보고서 안내(99,000원 · 신청서 링크)는 생성기 것 그대로 둔다. **토스 결제 심사 중이라 값 · 상품 구성은 손대지 않는다**
- 손으로 고친 문장은 다음에 생성기를 돌리면 사라진다. 여러 달에 두루 고칠 말은 생성기에서 고친다

## 대표 이미지

`assets/이미지틀.html` 을 복사해 내용만 바꾼다. 한지 팔레트와 인장이 이미 들어 있다.

- **정사각형(540×540)** — 네이버 모바일 피드가 정사각으로 자른다
- 글의 **한 문장**만 담는다. 숫자와 간지는 **덤프 결과 그대로**(으뜸 몇 곳, 걸리지 않는 낮 시각 몇 곳 같은 것). 점수는 넣지 않는다
- `Artifact` 도구로 게시하고 링크를 전달한다. 사용자가 카드 영역만 갈무리해 쓴다

## 옛것 — 쓰지 않음

2026-09-18 에 월별 글이 새 방식으로 바뀌었고, 2026-09-22 에 이 스킬에서도 없앴다. 파일은 지우지 않았다.

- `scripts/scan.js` — 조후 ±35 · 빈 오행 · 유통 · 통근 · 강약으로 그 달 안 서열을 0~100 으로 편 채점기. 맨 위에서 멈추게 해 두었다
- `.taekil/_taekil.json` — scan.js 산출(09-10). 점수 · 순위는 쓰지 않는다. `tools_form.py` 의 날짜-일주 대조에만 남아 있다
- `tools_taekil_gen.py` · `tools_taekil_verify.py` · `tools_taekil_review.py` — 옛 블로그 생성기(위 json 을 읽음). 쓰지 않는다
- 날마다 점수 한 줄 · 주간/야간 두 갈래 순위 · 「순위가 조건 하나로 뒤집혔다」는 예 · 세 고전마다의 점수 식
- `references/세고전.md` · `references/원고틀.md` 는 새 방식으로 다시 적었다
