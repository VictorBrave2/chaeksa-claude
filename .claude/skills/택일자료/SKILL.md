# 택일 자료 만들기

책사 엔진으로 기간을 계산해 블로그에 올릴 자료를 만드는 일이다.
매달 반복되는 작업이라, 매번 처음부터 생각하지 않도록 그동안 쌓인 판단을 여기 적어둔다.

산출물은 셋이다.

1. **계산 결과** — `marketing/계산결과-YYYY-MM.txt`. 상위·하위·반전 사례와 판단 근거.
   전량 덤프는 필요 없다. 글에 쓸 것과 왜 그걸 골랐는지가 남으면 된다.
2. **블로그판** — `marketing/붙여넣기-주제.html`.
   사용자는 버튼 한 번 누르고 네이버에 Ctrl+V만 하면 끝이다. 원고 `.txt`는 더 안 만든다 —
   두 벌을 만들면 고칠 때 한쪽만 고쳐서 어긋난다.
3. **보고서판** — 같은 계산을 의뢰인용 한 장짜리로. 기간 자료만 낼 때는 건너뛴다.
   `docs/10_두형식.md`
4. **대표 이미지** — `marketing/대표이미지-주제.html` → 아티팩트로 게시

`NN`은 `marketing/` 의 기존 `naver-*` 중 최대 번호 + 1. `주제`는 `10월출산택일` 처럼
검색어가 되는 말로 짧게. 파일을 전달할 때 `SendUserFile` 이 없으면 경로만 알려주면 된다.

## 왜 엔진을 브라우저에서 부르는가

명리 계산기는 전부 `app/*.js`에 있고 **브라우저에서만 돕니다.** Node로 못 씁니다.
그래서 `chaeksa.kr`을 열어 `javascript_tool`로 계산합니다.

```
mcp__Claude_Browser__preview_start  { url: "https://chaeksa.kr" }
mcp__Claude_Browser__javascript_tool { tabId, text: "<계산 스크립트>" }
```

로컬 변경을 반영해야 하면 `preview_start { name: "chaeksa-web" }`로 개발 서버를 씁니다.
다만 **자료용 계산은 라이브(chaeksa.kr)로 하는 게 낫습니다** — 독자가 보게 될 것과 같은 코드라야
"직접 넣어보시면 같은 결과가 나옵니다"가 참이 됩니다.

계산 스크립트는 `scripts/scan.js`에 있습니다. 그대로 붙여 쓰고, 맨 아래 `CONFIG`만 바꾸세요.

**결과는 `window.__택일` 에 남습니다.** `javascript_tool` 은 호출마다 스코프가 사라지므로,
상위 목록만 보고 끝낼 게 아니라면 다음 호출에서 `window.__택일._rows` 를 훑으세요.
360개를 다시 계산할 이유가 없습니다.

## 계산

### 무엇을 세는가

하루를 12시진으로 쪼갭니다. 한 달이면 약 360개 후보가 나옵니다.
`시지`는 두 시간 단위라 그 안에서는 사주가 같으므로, 12개가 완전한 해상도입니다.

각 후보마다 이것들을 뽑습니다.

| 항목 | 왜 보는가 |
|---|---|
| 오행 분포·빈 오행 | 빈 자리가 평생 약한 고리가 된다 |
| 유통 (생 사슬 최대 길이) | 기운이 한 바퀴 도는가, 고이는가 |
| 통근 (일간이 지지에 뿌리내린 곳 수) | "튼튼하다"의 실체. 강약보다 먼저 본다 |
| 강약 (`analysis.strength`) | 참고. **단독으로 쓰면 오해를 부른다** |
| 충·합 | 피할 수 있는 것과 없는 것을 나눈다 |
| 부모 일주와의 관계 | 아이 사주는 혼자 서지 않는다. 자료에서 흔히 빠진다 |

**점수는 절대값이 아닙니다.** 그 기간 안의 서열을 0~100으로 편 것이라,
다른 달의 점수와 비교하면 안 됩니다. 글에도 그렇게 밝히세요.

**`시각` 은 태양시, `시계` 는 실제 시계 시각입니다.** 둘이 30분 넘게 어긋납니다.
독자가 병원에 말할 것은 `시계` 쪽이니, 원고에 옮길 때 이걸 헷갈리면 자료가 통째로 틀립니다.

### 강약을 앞세우지 말 것

`신강 0.62`가 `중화 0.49`보다 좋아 보이지만 자주 그 반대입니다.
물이 많아 세 보이는데 통근이 0이고 유통이 2/5인 경우가 실제로 나옵니다.

**한 가지 숫자만 보면 정반대로 고르게 된다** — 이게 이 자료가 파는 통찰입니다.
계산 결과에서 그런 사례가 나오면 반드시 글에 넣으세요. 없으면 억지로 만들지 마세요.

### 피할 수 없는 충

연주와 월주는 그 달에 고정입니다. 예컨대 2026년 12월은 `丙午년 庚子월`이라
**모든 후보에 연지-월지 충(午子)이 있습니다.** 날짜를 아무리 골라도 안 없어집니다.

이럴 때 "충이 있으니 나쁘다"는 말은 의미가 없습니다.
글에서 **고를 수 있는 충과 없는 충을 나눠주면** 독자가 다른 자료를 볼 눈이 생깁니다.

### 주간·야간을 함부로 자르지 말 것

처음엔 "병원은 낮에만 수술하니 주간만 계산하자"고 하기 쉽습니다. **그러면 안 됩니다.**
밤이든 새벽이든 예약 수술이 되는 병원이 있고, 그게 가능한 사람에게 최선을 감추는 건 자료가 아닙니다.

24시간 전부 계산하고 `[주]`/`[야]`를 표시한 뒤, 순위를 **두 갈래로** 냅니다.

- 야간까지 조율 가능한 분 → 전체 순위
- 일반 스케줄만 가능한 분 → 주간 순위

### 세 고전 관점 (선택)

`references/세고전.md`에 자평진전·적천수·궁통보감 **채점 규칙**이 있습니다.
실행 가능한 코드가 아니라 산문 스펙이므로, 쓰기로 했으면 격 판정 로직을 직접 짜야 합니다.

**언제 쓰는가** — 기본 채점만으로 이야기가 안 나올 때. 상위권이 다 비슷비슷하거나
반전 사례가 없으면 세 관점을 넣어 "어디서 갈리는지"를 콘텐츠로 만듭니다.
기본 채점에서 이미 좋은 대비가 나왔으면 굳이 넣지 마세요. 글만 길어집니다.

**궁통보감은 통용 판본 조후용신표 120칸**을 그대로 씁니다(classic.js, 표 전문은 docs/12).
판본이 갈리는 칸이 있으므로 "통용 판본 기준"임을 글에 밝힙니다.

세 관점은 서로 상관이 거의 없습니다(자평-적천 −0.18). 그래서 셋을 다 쓰면
**어디서 갈리는지**가 콘텐츠가 됩니다. 하나로 합쳐 평균 내면 그 값어치가 사라집니다.

## 진태양시 시각 창 — 이 자료의 핵심

여기가 다른 데서 못 보는 부분입니다. 절대 빼지 마세요.

한국은 동경 135도를 표준으로 쓰는데 그 선은 일본을 지납니다.
그래서 **시계 시각과 사주의 시(時)가 다릅니다.**

```
서울 32분 밀림
09:00 수술 → 태양시 08:28 → 辰시   ← 巳시가 아니다
09:31 수술 → 태양시 08:59 → 辰시
09:32 수술 → 태양시 09:00 → 巳시   ← 여기부터
```

엔진은 **표시되는 분을 기준으로** 시진을 잡습니다. 태양시가 정각이 되는 분부터
다음 시진입니다. 지역 보정이 32분이면 시계 32분부터, 24분이면 24분부터입니다.
(출생 시각은 분 단위로 기록되므로 초 단위는 따지지 않습니다)

지역별 편차: 목포·제주 34분 · 인천 33분 · 서울 32분 · 대구 26분 · 강릉·부산 24분 · 울산 23분

**시주를 정해놓고 병원에 정시를 요청하면 의도한 것과 다른 시주가 나옵니다.**
계산에서 `result.corrected`가 보정된 실제 시각입니다. 시각 창 표를 반드시 글에 넣으세요.

## 블로그 원고

`references/원고틀.md`에 절 구성과 문장 예시가 있습니다. 처음 쓸 때 읽으세요.

### 빼면 안 되는 두 문단

**1. 의료 면책** — 출산택일은 제왕절개·유도분만 일정입니다. 맨 앞에 놓습니다.

> 출산 날짜는 의사가 정합니다. 산모의 상태, 아기의 크기와 자세, 태반 위치, 병원 수술 일정.
> 이런 의학적 판단이 언제나 먼저입니다. 명리 택일은 그 다음입니다.
> 의학적 판단을 뒤집는 용도로 쓰시면 안 됩니다.

**2. 정직성 문단** — 채점 비중을 내가 정했다는 것, 유파에 따라 다르다는 것, 대운은 성별로 갈린다는 것.

> 이 자료는 정답이 아니라 '이 기준으로는 이렇게 나왔다'입니다. 기준을 공개하는 이유가 그것입니다.

이 둘이 이 블로그의 무기입니다. 첫 글에서 *"기준을 밝히지 않는 것이 문제입니다"*라고 썼으니,
여기서 얼버무리면 나머지 주장이 같이 무너집니다.

### 실제 사람의 상담을 자료로 쓰지 말 것

댓글로 받은 질문을 글로 옮기고 싶어질 때가 있습니다. **동의 없이는 안 됩니다.**
"익명이니까 괜찮다"는 틀립니다 — 댓글이 공개로 남아 대조 가능하고, 본인은 반드시 알아봅니다.

대신 **같은 구조를 직접 만들어** 쓰세요. 값어치는 그 사람의 데이터가 아니라 방법에 있습니다.
가상 사례로 쓸 때는 본문에 *"이해를 돕기 위해 만든 가상의 사례입니다"*라고 밝힙니다.

### 네이버 모바일 서식 — 붙여넣기 페이지로 낸다

`.txt` 원고에 `■`, `▸` 같은 표시를 달아 두고 사용자가 에디터에서 서식을 다시 잡던
방식은 그만뒀다. 손이 많이 가고, 옮기다 보면 빠진다.

지금은 **`marketing/붙여넣기-주제.html`** 한 장으로 낸다.
기존 `붙여넣기-*.html`을 복사해 `#doc` 안만 갈아끼우면 된다.
복사 버튼이 서식이 살아 있는 채로 클립보드에 넣으므로,
사용자는 **버튼 → 네이버 본문에 Ctrl+V → 제목만 따로 입력**이면 끝이다.

네이버가 살려주는 태그는 `h2 h3 p b i hr blockquote` 정도뿐이다.
**class와 inline style은 버려진다.** 그 안에서 짜야 한다.

- **표는 절대 금지.** PC에서는 멀쩡한데 모바일에서 본문이 통째로 옆으로 밀린다.
  숫자 비교는 전부 `<blockquote>` 안의 `▸` 줄로.
- **한 문단 한 호흡.** 45자가 넘으면 폰에서 서너 줄로 접힌다. 마침표마다 `<p>`를 나눈다.
- 제목은 `<h2>`, 부제는 `<p class="alt">`, 해시태그는 `<p class="tag">`.
  이 셋은 복사할 때 빠지거나 따로 쓰인다.

다 쓰고 나면 반드시 돌린다. 형식이 섞이면 조용히 망가진다.

```
python tools_form.py
```

`X`가 하나라도 있으면 올리지 않는다. 자세한 것은 `docs/10_두형식.md`.

### 마무리는 댓글을 부르는 문장으로

> 후보를 받으셨는데 판단이 어려우시면 댓글로 남겨주세요.
> 날짜와 시간, 태어날 지역만 알려주시면 계산해서 알려드리겠습니다.

첫 글에서 이 형태로 실제 상담 문의가 왔습니다. 공개 댓글로 받으면 동의 문제도 없습니다.

## 대표 이미지

`assets/이미지틀.html`을 복사해 내용만 바꿉니다. 한지 팔레트와 인장이 이미 들어 있습니다.

- **정사각형(540×540)** — 네이버 모바일 피드가 정사각으로 자릅니다. 이 비율이 안전합니다.
- 글의 **한 문장**만 담습니다. 요약하려 들면 아무것도 안 남습니다.
- 숫자와 간지는 **실제 계산 결과** 그대로. 임의로 고치면 본문과 어긋납니다.

`Artifact` 도구로 게시하고 링크를 전달합니다. 사용자가 카드 영역만 캡처해 씁니다.

## 작업 순서

1. 기간과 지역을 확인한다. 안 밝혔으면 서울로 두고 **그 사실을 글에 적는다**.
   성별도 안 밝혔으면 그냥 진행한다 — 원국은 성별과 무관하고 대운 방향만 갈린다.
   대신 정직성 문단에 "대운은 성별로 갈린다"를 넣는다.
2. `chaeksa.kr`을 열고 `scripts/scan.js`로 계산한다.
3. 결과를 훑어 **이야기가 되는 지점**을 찾는다 — 통근 0인 후보, 강약과 실질이 어긋나는 후보,
   공동 1위, 피할 수 없는 충. 없으면 없다고 쓴다. 억지로 만들지 않는다.
4. 원고를 쓴다. 의료 면책과 정직성 문단을 먼저 자리잡고 나머지를 채운다.
5. 대표 이미지를 만들고 게시한다.
6. 원고 파일을 `SendUserFile`로 전달하고, 이미지 링크를 함께 준다.

계산 결과를 사용자에게 보고할 때는 **표를 쓰되 숫자를 해석해서** 보여주세요.
`유통 2/5`가 무슨 뜻인지 모르면 표가 아무 값어치가 없습니다.
