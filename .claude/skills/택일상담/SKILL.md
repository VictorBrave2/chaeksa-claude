# 1:1 택일 상담

블로그 댓글 · 신청서로 들어온 한 사람의 문의에 답하는 일이다. 99,000원 보고서도 같은 흐름이다.

점수 · 순위 · TOP N을 낼 수 있다(09-25 법전 60조 삭제).
사이트 월별 글(`tools_wolbyeol.py`)과 시뮬레이터(`app/taekilsim.js`)가 2026-09-18부터 이 방식이다.
상담이 다른 말을 하면 의뢰인이 우리 글을 봤을 때 숫자가 어긋나고, 「기준을 공개한다」는 말이 무너진다.

| | 택일자료 | 택일상담 |
|---|---|---|
| 입력 | 년월 | 기간 + 물어본 시각 + 가족 생일 + 성별 + 병원 시간 |
| 거르기 | 두 고전 | 두 고전 → 가족 일지 충 → 병원 시간 |
| 대운 | 안 본다(보고서 몫) | 본다 — 성별로 갈린다 |
| 산출 | 월별 글 + 카드 | 답글(붙여넣기) + 카드 |
| 핵심 | 방법을 보여준다 | **답을 정해준다** — 권하는 순서는 사람이 까닭과 함께 |

---

## 판정이 하는 것

전부 판정엔진(`app/panjeong.js`) + 출산택일 관점(`app/gwanjeom.js`)이 한다. 여기서 새로 재지 않는다.

- **궁통보감 = 거르개** — 태어난 달 · 일간으로 표(120칸)에서 먼저 찾는 글자를 정하고, 그 글자가 천간에 있나. 없으면 걸림
- **자평진전 = 거르개** — 무슨 격이고 파격인가. 파격이면 걸림. 격을 하나로 못 잡으면 「모름」(걸림 없음으로 치지 않는다)
- **적천수 = 참고** — 걸림을 매기지 않는다. 기세 · 흐름 · 통관을 한 줄로 읽기만 한다
- **걸리는 것 없음** = 두 거르개 모두 걸림 없음 (`본.없음`)
- **으뜸** = 걸리는 것 없음 + 궁통보감이 적어 둔 글자(먼저 찾는 글자 + 돕는 글자)가 천간에 다 있음 (`본.으뜸`)

격 성패를 말로 옮길 때는 **성격 · 구응 · 기신 있음 · 파격** 넷만 쓴다(`feedback-four-verdict-terms`).
기계는 「파격인가 아닌가」까지만 믿는다(원문 실례 22건 중 성패 판정 11건만 맞음 — `project-chaeksa-taekil-scoring`).

**걸리는 것 없는 곳들 사이의 순서는 기계가 가르지 않는다.** 병원 시간 · 가족 · 대운을 사람이 읽고
「이래서 이쪽을 먼저 권한다」를 말로 적는다. 숫자로 가르고 싶어지면 그게 함정이다.

## 순서

```
1  문의에서 뽑는다      기간 · 태어날 곳 · 성별 · 물어본 시각 · 가족 생년월일시 · 병원 가능 시간
2  개발 서버 + 수신기    preview_start chaeksa-app · python tools_sangdam_gen.py 받기
3  가족 일주를 구한다    브라우저에서 ChaeksaEngine.calc
4  기간을 덤프한다       브라우저에서 ChaeksaTaekilSim.하루 + ChaeksaGwanjeom.대운 → JSON
5  첫 판을 짠다          python tools_sangdam_gen.py 짜기 … --no-cards  → 터미널에 남은 곳 목록
6  권하는 순서를 정한다   병원 시간 → 가족 → 대운을 읽고, 까닭을 말로
7  카드 + 답글을 짠다     --order · --summary 를 넣어 다시 짜기 → 카드 PNG + 붙여넣기.html
8  눈으로 확인하고 보낸다  카드 그림 · 답글 글 · 대운 줄을 쉬운 말로 다듬기
```

**없는 정보 때문에 멈추지 않는다.** 없는 건 비워 두고 먼저 답을 드린 뒤 「알려 주시면 다시 보겠습니다」로 연다.
가족 정보를 받아야 시작할 수 있다고 하면 대부분 거기서 대화가 끊긴다.

- 지역을 모르면 **서울**로 하고 답글에 적는다(생성기가 조건 상자에 적는다)
- 성별을 모르면 원국은 같다 — 대운만 갈린다. `--no-daeun` 으로 대운을 빼고 「성별을 알려 주시면 대운까지 봐 드릴게요」를 붙인다
- 가족 생일이 없으면 `--family` 를 비운다. 가족은 **좋은 곳을 찾는 재료가 아니라 부딪히는 곳을 거르는 체**다
- 병원 시간을 모르면 `--window` 를 비운다. 대신 곳마다 병원 시간 등급(아래 표)이 붙는다

**담당 선생님 시간표를 받아라.** 시간표 없이 보면 잡을 수 없는 시각을 첫째로 내놓게 된다.

## 계산

### 1. 개발 서버와 탭

```

tabs_create → 받은 tabId 로 navigate http://localhost:8791/tests_taekilsim.html
```

탭은 **자기 탭을 따로 열고 그 tabId 만 쓴다**(창 하나를 여럿이 같이 쓸 때가 있다).
서비스워커가 옛 파일을 물고 있으면 먼저 푼다 — 옛 엔진으로 재게 된다.

```js
for (const r of await navigator.serviceWorker.getRegistrations()) await r.unregister();
for (const k of await caches.keys()) await caches.delete(k);
```

개발 서버는 저장소의 `app/` 그대로다. 배포 전에 엔진을 고쳤다면 라이브와 다를 수 있으니,
답글을 보내기 전에 `chaeksa.kr/taekil-sim.html` 에 한 날짜를 넣어 같은 말이 나오는지 한 번 맞춰 본다.
의뢰인이 직접 넣어 봐도 같은 결과가 나와야 「직접 확인하실 수 있어요」가 참이 된다.

### 2. 수신기

`javascript_tool` 은 긴 결과를 돌려주지 못한다(8일 덤프가 250KB쯤). 그래서 로컬 수신기로 받는다.

```

```

### 3. 가족 일주

생년월일시로 일주를 구한다. 시각을 모르면 `hour:null`(밤 11시 반 무렵이 아니면 일주는 같다).
음력이면 `ChaeksaLunar.lunarToSolar(y, m, d, 윤달여부)` 가 `{y, m, d}` 양력을 준다.

```js
const E = ChaeksaEngine;
const 일주 = (y, m, d, h = null, mi = 0) => { const R = E.calc({ year: y, month: m, day: d, hour: h, minute: mi, gender: 'M', longitude: 126.98 });
  return E.STEMS[R.pillars.day.stem] + E.BRANCHES[R.pillars.day.branch]; };
({ 아버님: 일주(1990, 5, 3, 14, 20), 어머님: 일주(1992, 8, 11) })
```

### 4. 기간 덤프

맨 위 넷(성별 · 곳값 · 첫날 · 끝날)만 바꾼다. 곳값은 `app/places.js` 의 값(`KR:서울`, `KR:천안` …).

```js
const S=ChaeksaTaekilSim, E=ChaeksaEngine, W=ChaeksaGwanjeom, PL=ChaeksaPlaces;
const 성별='M', 곳값='KR:서울', 첫날='2026-10-21', 끝날='2026-10-28';
const 요일='일월화수목금토', 곳=PL.resolve(곳값), days=[];
const [a1,a2,a3]=첫날.split('-').map(Number), [b1,b2,b3]=끝날.split('-').map(Number);
for (let t=new Date(a1,a2-1,a3); t<=new Date(b1,b2-1,b3); t.setDate(t.getDate()+1)) {
  const y=t.getFullYear(), m=t.getMonth()+1, d=t.getDate(), h=S.하루(y,m,d,성별,곳값);
  days.push({y, m, d, 요일:요일[t.getDay()], 밀림:h.밀림, 곳:h.곳, rows:h.rows.map(r => {
    const o={시진:r.시진, 창:r.창, 시작:r.시작, 끝:r.끝, 일주:r.일주, 시주:r.시주, 월주:r.월주, 연주:r.연주, 밤끝:!!r.밤끝,
      걸림수:r.본?r.본.걸림수:null, 없음:!!(r.본&&r.본.없음), 으뜸:!!(r.본&&r.본.으뜸),
      눈:r.본?r.본.눈들.map(n=>({key:n.key, 고전:n.고전, 걸림:!!n.걸림, 모름:!!n.모름, 보조:!!n.보조, 한줄:n.한줄, 풀이:n.풀이})):[]};
    if (o.없음) { const c=Math.floor((r.시작+r.끝)/2);
      const R=E.calc({year:y, month:m, day:d, hour:Math.floor(c/60), minute:c%60, gender:성별, longitude:곳.lon, tzOffset:곳.tzOffset});
      o.대운=W.대운(R,성별).map(x=>({간지:x.간지, 시작나이:x.시작나이, 끝나이:x.끝나이, 줄:x.줄})); }
    return o; })});
}
const res = await fetch('http://127.0.0.1:8793/consult.json', {method:'POST', body:JSON.stringify({성별, 곳값, days})});
({ok: res.ok, 날수: days.length, 깨끗: days.flatMap(d=>d.rows.filter(r=>r.없음).map(r=>d.d+'일 '+r.시진+' '+r.창+(r.으뜸?' 으뜸':'')))})
```

### 하루가 돌려주는 것

```
ChaeksaTaekilSim.하루(y, m, d, 'M'|'F', 'KR:서울') → { rows, 곳, 밀림 }
  밀림            그날 시계가 해보다 빠른 분(서울 10월 16분쯤, 12월 28분쯤 — 날마다 다르다)
  rows[]          그날 시진 창 13개. 자시가 새벽 앞(00:00~)과 밤 끝(23:1x~) 두 번 나온다
    창            '17:16~19:15' — 병원에 말할 시계 시각. 엔진에 분 단위로 물어 정한 경계다
    시작 · 끝     0시부터 센 분(끝은 그 분까지 포함)
    시진          '유시'
    일주 · 시주 · 월주 · 연주   '계유(癸酉)' 꼴
    밤끝          밤 11시 넘은 자시 — 이때 낳으면 다음 날 일주
    본.걸림수     두 거르개(궁통보감 · 자평진전) 가운데 걸린 수
    본.없음       두 고전 모두 걸리는 것 없음(모름도 없어야 참)
    본.으뜸       없음 + 궁통보감이 적은 글자가 천간에 다 있음
    본.눈들[]     { key: '조후' | '격' | '통관', 고전, 걸림, 모름, 보조(적천수는 true), 한줄, 풀이[] }
```

시진 경계를 손으로 셈하지 않는다. 교과서 시진표(미시 = 13:00~14:59)로 적으면 다른 사주가 된다.

### 대운

`ChaeksaGwanjeom.대운(R, 성별)` — R 은 `ChaeksaEngine.calc(...)` 결과. 돌려주는 것은
`[{ 간지, 시작나이, 끝나이, 시작해, 줄[] }]` 이고, 줄에는 천간 · 지지 십신(이름 + 뜻), 계절이 찾던 글자가 오는지,
격이 이어지나 바뀌나, 원국과의 충 · 합 · 삼합(어느 궁인지)이 들어 있다.
`tests_taekilsim.html` 은 `samyeong.js` 를 안 불러서 귀인 · 십이운성 줄은 안 나온다. 상담에는 없어도 된다.

생성기는 앞 다섯 대운을 한 줄씩 줄여 옮긴다(천간 · 지지 십신, 원국과의 충, 계절 글자, 격 바뀜).
**답글에서는 그 줄을 쉬운 말로 풀어 쓴다** — 「열 살 무렵부터 서른 초반까지 오는 운에 사주와 부딪히는 글자가 없어서…」처럼.
충 · 합의 뜻은 사장님 말 그대로 쓴다: 「충은 글자의 십성이 발현되거나 있던 것이 깨질 수 있어요」
「합은 글자의 십성이 묶여서 기능을 잃거나 합생할 수 있어요」. 좋다 나쁘다로 단정하지 않는다.

### 5 ~ 7. 짜기

```
python tools_sangdam_gen.py 짜기 <scratchpad>/consult/consult.json --name 2026-10-son \
    --family "아버님:丁丑,어머님:壬辰" --asked "2026-10-26T15:00" --window 7-21 --no-cards
```

터미널에 남은 곳 목록이 나온다(날짜 · 시진 · 창 · 격 · 으뜸 · 병원 시간 등급 · 대운 충 나이 · 시지 충).
거기서 권하는 순서를 정해 다시 짠다.

```
python tools_sangdam_gen.py 짜기 … --order "10-26 유,10-28 미,10-23 신" \
    --summary "병원 일정과 제일 잘 맞는 건 1번(26일 저녁)이에요.|저녁 수술이 어렵다면 2번(28일 오후)을 권해 드려요."
```

| 옵션 | 뜻 |
|---|---|
| `--name` | 카드 폴더 이름(영문 · 숫자 · -). `app/cards/consult-<name>/` |
| `--family` | `이름:일주` 를 쉼표로. 일지 한 글자(`아버님:丑`, `아버님:축`)도 된다 |
| `--asked` | 물어본 시각 `2026-10-26T15:00`. 걸리면 걸린 대로 적고, 카드도 먼저 찍는다 |
| `--order` | 권하는 순서 `10-26 유` 꼴. 걸린 곳 · 가족 충으로 뺀 곳은 넣을 수 없다(멈춘다) |
| `--summary` | 정리 문단. `\|` 로 문단을 나눈다. 첫 문단은 굵게. **까닭을 말로** |
| `--window 7-21` | 병원이 된다고 한 시간. 밖이면 뺀다 |
| `--strict` | 아이 **시지**가 가족 일지와 부딪히는 곳도 뺀다(기본은 일지만 빼고 시지는 적기만) |
| `--cards 3` | 권하는 곳 카드 장수(물어본 시각 카드는 따로) |
| `--no-cards` · `--no-daeun` | 카드 안 찍음 · 대운 뺌(성별 모를 때) |

나오는 것:

- `marketing/cards/상담-<name>/붙여넣기.html` — 답글. **부모 일지가 들어 있다. 커밋하지 않는다.**
- `app/cards/consult-<name>/01.png …` — 명식 카드(아기 시각만). 커밋 · 배포해야 `https://chaeksa.kr/cards/…` 주소가 산다.

### 가족은 이렇게 거른다

- 아이 **일지**가 가족 누구의 일지와 충(子午 · 丑未 · 寅申 · 卯酉 · 辰戌 · 巳亥)이면 뺀다 — 「가족과 부딪혀서 뺀 곳」으로 따로 적는다
- 아이 **시지**의 충은 적어 두기만 한다(09-21 상담에서 쓴 기준). 의뢰인이 가족을 앞세우면 `--strict`
- **합에는 아무 값도 주지 않는다.** 적기만 한다. 합이 순위를 사면 부모와 잘 맞물리지만 아이 사주는 평범한 곳을 권하게 된다
- 걸러서 남는 곳이 없으면 그대로 말한다. 뺀 곳은 「두 고전으로는 걸리는 것이 없다」고 적어 두고 고르시게 한다

| 야간 | 19~07시 | 시간을 맞춰주는 병원을 찾아야 한다 |
| 주말 | 토 · 일 | 예약 수술은 어렵다 |

**주말을 빼먹지 마라.** 날짜만 보고 요일을 안 보면 일요일 새벽을 첫째로 내놓게 된다.
창이 평일 낮과 조금만 겹치면(예: 104분 중 16분) 생성기가 겹치는 분을 적는다. 병원이 조금만 늦어도 시주가 바뀐다.

## 답글 형식

월별 글과 **같은 붙여넣기 틀**이다(메모리 `feedback-consult-reply-format`). 생성기가 이 틀로 낸다. 새 모양을 지어내지 않는다.

- 위에 초록 **「본문 전체 복사」** 단추, 본문은 `.wrap` 안의 `#doc`
- 카드는 `<p class="card-img"><img src="https://chaeksa.kr/cards/consult-<name>/01.png">` — 네이버에 붙이면 그림이 따라간다
- 그 아래 `<p class="alt">` 안내 줄(「그림이 안 따라오면 이 파일을 끌어다 놓으세요」)은 **복사할 때 빠진다**
- 본문에 `**` 같은 마크다운 기호를 쓰지 않는다. 굵게는 `<b>`
- 카드 순서와 본문 번호를 맞춘다: 물어본 시각 → 1번 → 2번 …
- 카드 라벨에 쉼표를 넣지 않는다(명식 카드 주소에서 쉼표로 나눈다)

생성기가 낸 글은 **초안**이다. 보내기 전에 손으로 다듬는다.

1. 대운 줄(▸ 목록)을 두세 문장의 쉬운 말로 푼다. 목록은 남겨도 되지만 풀어 쓴 말이 먼저다
2. 정리 문단(`--summary`)에 **왜 이 순서인지**를 적는다 — 병원 일정, 가족, 대운 초반에 부딪히는 글자가 있나
3. 맞바꿈이 있으면 감추지 않는다(아래)
4. 말투는 `~어요` 로, 메모리의 말투 규칙(`feedback-my-dialect-is-the-problem` · `feedback-plain-for-anyone`)을 따른다

빼면 안 되는 것 셋(생성기가 넣는다):

1. **의료 면책** — 출산 날짜는 담당 선생님이 정한다
2. **「받으신 택일이 틀렸다고 말하지 않습니다」** — 기준이 다르면 답도 다르다. 남을 깎는 순간 이 블로그의 무기가 무뎌진다
3. **시계 시각** — 병원에 「유시에」가 아니라 「오후 5시 16분 이후로」라고 말하게

**받은 곳이 어디인지 묻지 않는다.** 물으면 비교 게시판이 된다.
상담을 닫을 때는 **출산 후 확정된 시각을 알려주시면 최종 사주를 확인해 드린다**고 열어둔다.

값과 받는 곳은 `references/답글틀.md` 「값과 받는 곳」을 그대로 따른다. **토스 결제 심사 중이라 값 · 상품 구성은 손대지 않는다.**

## 판단할 때 조심할 것

### 피할 수 없는 충을 나눠라

연주와 월주는 그 달에 고정이다. 예컨대 2026년 12월은 `丙午년 庚子월`이라 **모든 시각에 연지-월지 충이 있다.**
날짜를 골라도 안 없어진다. 의뢰인이 다른 곳에서 「충이 있어 나쁘다」는 말을 들었다면 이걸 짚어주는 것만으로 큰 도움이 된다.

### 맞바꿈은 맞바꿈이라고 말해라

한 시각이 모든 것에서 가장 나은 경우는 드물다. 이런 모양이 자주 나온다.

- 두 고전에 안 걸리는데 평일 낮이 아니다(26일 저녁처럼)
- 평일 낮인데 아이 시지가 아버님 일지와 부딪힌다
- 원국은 걸리는 것이 없는데 대운 초반에 부딪히는 글자가 온다

한쪽을 감추고 「이게 최고입니다」라고 하지 않는다. **무엇과 무엇을 바꾸는 것인지 보여주고 고르시게 한다.**
대신 정할 수 없는 영역이라는 것도 말한다. 「완벽한 시각」은 없다.

### 앞세우는 것을 말하면

「출세했으면」「건강했으면」「공부를 잘했으면」 같은 말을 받으면 **기계 쪽을 바꾸지 않는다**(옛 우선순위 프리셋은 없앴다).
걸리는 것 없는 곳들의 대운 줄 — 천간 · 지지 십신(이름 + 뜻), 계절이 찾던 글자가 언제 오는지, 격이 바뀌는 때 — 을 읽고
그 바람에 가까운 곳을 `--order` 앞에 두고, 까닭을 `--summary` 에 말로 적는다. 되물어서 뜻을 좁힌다
(「재관」이라 해도 돈 쪽인지 직업 쪽인지에 따라 읽는 줄이 다르다).

### 원국이냐 대운이냐

원국은 걸리는 것이 없는데 대운이 늦게 열리는 곳, 원국은 평범한데 젊을 때 운이 채우는 곳이 자주 반대로 간다.
의뢰인이 「대운이 좋았으면」이라 했으면 앞쪽, 「잘 타고났으면」이면 뒤쪽이다. 어느 쪽도 정답이 아니므로 나란히 놓고 고르시게 한다.

## 블로그판도 함께 낸다

상담 한 건에서 나온 발견은 대개 **글 한 편이 된다.** 다만 **의뢰인의 사연은 못 옮긴다.** 익명이어도 안 된다 —
댓글이 공개로 남아 있어서 기간과 가족 구성만으로 특정되고, 본인은 반드시 알아본다.

- **뺀다** — 가족 일주, 분만예정 기간, 받으신 택일, 의뢰인이 한 말
- **남긴다** — 계산 방법, 간지, 판정 까닭
- **바꾼다** — 「이 아이는」 → 「이런 시각은」, 사례 → 만든 예

**「지난 상담에서」「실제 사례」「의뢰인」이라는 말 자체를 쓰지 않는다**(2026-09-16 사장님).
글은 **만든 예**로 쓰고 「이해를 돕기 위해 만든 사례입니다」라고 밝힌다. `python tools_form.py` 가 막는다.
형식 규칙은 `docs/10_두형식.md`.

## 왜 이 상담이 통하는가

상담은 대개 같은 길로 온다: **다른 곳에서 택일을 받고, 미심쩍어서 확인하러 온다.** 그리고 결과가 아니라 **근거를 보고** 남는다.
그래서 산출물은 답이 아니라 **답에 붙은 근거의 두께**다 — 모든 날 모든 시각을 본 것, 두 고전이 각자 본 것,
가족 충, 대운, 시계 시각, 명식 카드, 그리고 chaeksa.kr 시뮬레이터에서 직접 확인할 수 있다는 것.
남의 택일을 깎지 않아도 근거의 양이 승부를 낸다.
