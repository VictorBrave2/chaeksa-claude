# 수익 구조 — 원가와 매출

걱정하신 "토큰값이 매출보다 높은 상황"은 **구독자에게는 해당하지 않습니다.**
실측 토큰(입력 2,720 · 출력 250)으로 계산한 결과입니다.

## 진짜 위험은 여기였습니다

**무료 사용자에게 AI를 무제한으로 열어둔 것.**
지금까지는 로그인 없이도 프록시의 IP당 하루 40회 안에서 누구나 AI를 쓸 수 있었습니다.
한 사람이 그 한도를 매일 다 쓰면 **월 22,599원** — 구독료의 두 배가 넘습니다.

즉 문제는 "토큰이 비싸다"가 아니라 **"공짜로 나가는 구멍"** 이었습니다.

## 설계 원칙

> **한계비용이 0인 것은 아낌없이 주고, AI를 부르는 것만 한도를 둔다.**

만세력·원국·대운·세운·월운·택일 달력·궁합 점수·규칙 기반 브리핑은
**전부 사용자 기기에서 계산**됩니다. 서버 비용이 0이므로 제한할 이유가 없습니다.
이건 인심이 아니라 구조입니다 — 아껴봐야 한 푼도 안 남습니다.

## 원가가 매출을 넘지 못하게 하는 3중 장치

1. **화면 단계** — `app/usage.js`. 등급별 월 한도. 초과하면 규칙 기반 결과로 자동 전환되어 서비스는 멈추지 않습니다. ✅ 적용됨
2. **서버 단계** — 프록시가 로그인 토큰을 확인하고 사용자별 한도를 강제. ⬜ 예정 (아래)
3. **최종 방어선** — Anthropic 콘솔의 월 지출 한도. ⬜ **지금 바로 설정 권장**

1번만으로는 브라우저 저장소를 지우면 우회됩니다. 지인 테스트 단계에서는 충분하지만,
공개 전에는 2번이 반드시 필요합니다.

### 2번을 켜는 방법 (나중에)
프록시(`api/chat.js`)가 요청의 로그인 토큰을 Supabase에 확인하고,
사용자별 사용량을 서버 표에 기록해 한도를 강제합니다.
Vercel 환경변수에 `SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE`을 추가해야 합니다.

## 비용을 더 줄이는 방법

입력 토큰(2,720)이 출력(250)보다 훨씬 큽니다. 원국과 고정 해석이 매번 반복되기 때문입니다.
**프롬프트 캐싱**을 붙이면 반복되는 앞부분이 1/10 가격이 됩니다.
특히 대화에서 효과가 크며, 대화 원가를 18.8원 → 약 7원으로 낮출 수 있습니다.
