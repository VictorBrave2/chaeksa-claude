## 전략

**한 줄: 앞은 지금 그대로 보여 주고, 뒤는 제목만 남기고 본문을 짓지 않는다. 값은 상품표 한 곳에서, 열쇠는 사람 · 쌍마다, 결제는 결제 화면 한 장에서 받는다. 돈이 들어온 주문만 열고, 산 사람 화면에는 잠금이 있었다는 흔적이 없다.**

지키는 것 아홉.

1. 값은 DB `products` 한 곳에만 있다. 화면 · 코드에 숫자를 적지 않는다(app/pay.js:8-9).
2. 자르는 곳은 회 · 장 번호 상수다. 어떤 명식 · 어떤 쌍이 와도 같다. 예외는 하나다 — 웹툰궁합 「시작 전」 단계만 첫 회가 아니라 손님이 고른 한 회를 연다(여는 회 수는 같다 · 2절 라).
3. 잠긴 본문은 문자열을 지을 때부터 넣지 않는다. 다 지은 뒤 화면에서 덜어 내는 방식은 쓰지 않는다.
4. 산 사람 화면에는 잠금 글자 · 값 · 결제 상자가 하나도 없다(메모 feedback-paid-content-generosity).
5. 잠금은 화면 층에만 넣는다. 엔진 · 관점 · 뼈대 · 조립기는 건드리지 않는다.
6. 스위치는 하나다(`app/config.js` 의 `CHAEKSA_LOCK`). 모르면 잠근다 — 스위치가 켜졌는데 잠금 정보가 없으면 무료 범위만 그린다.
7. 스위치를 켜는 날은 고친 약관의 적용일자와 라이브 키가 들어온 날 가운데 늦은 날이다. 그 전에는 다 만들어 배포해 두되 꺼 둔다.
8. 이미 산 것을 또 사는 길은 화면과 서버 두 곳에서 막는다.
9. 승인 응답의 상태가 `DONE` 인 주문만 결제완료로 적는다. 환불한 주문은 다시 잠근다.

### 0. 결제 화면 다시 짜기 (app/pay.html)

구조만 따른다. 디자인 · 문구 · 그림은 우리 것이다.

| 차례 | 칸 | 무엇으로 채우나 |
|---|---|---|
| 머리 | 돌아가기 · 제목 · 대상 줄 | 대상 줄 = 누구 것이 열리는지. 이름(없으면 관계)과 생년월일 날짜. 묶음이면 든 상품마다 한 줄 |
| ① | 상품 고르기 — 라디오 카드 | 골라져 온 단품 · 「추천」 묶음 · 전체 묶음. 카드마다 그림 · 이름 · 한 줄 설명 · 든 것 · 값. 전부 `products` 표에서 |
| ② | 결제수단 | 토스 결제위젯이 그리는 목록 그대로. 우리가 고르거나 빼지 않는다 |
| ③ | 결제 금액 상자 | 상품값 · 묶음 할인 · 최종 결제금액 |
| ④ | 동의 | 토스 약관 위젯 + 우리 [필수] 둘(개인정보 이용 · 청약철회 제한 — 지금 있는 동의 포함) |
| ⑤ | 화면 아래 붙은 큰 단추 | 「○○원 결제하기」. 금액은 고른 카드의 값 |
| 꼬리 | 환불 · 제공기간 안내 · 출산택일로 가는 길 · 사업자 정보 | 사업자 정보 줄은 지금 그대로 둔다(안 건드림) |

**넣지 않는 것**
- 휴대폰 번호 칸. 결제는 로그인 계정에 매인다. 토스 결제 요청에서 휴대폰 번호는 선택 값이다(공식 문서 확인 · 09-29).
- 판 적 없는 정가와 할인율. 할인은 묶음 할인 하나뿐이다.
- 출산택일. 신청 절차가 달라 묶음에 넣지 않고, 꼬리에서 신청 페이지(taekil-apply.html)로 가는 길만 둔다.

**카드를 그리는 규칙**

| 때 | 화면 |
|---|---|
| 유효 잠금이 꺼져 있다(4절) | 세 상품 · 묶음 카드를 그리지 않는다. 출산택일로 가는 길만 둔다. 앱은 전부 무료인데 결제 화면에만 값이 붙는 일을 막는다 |
| 단품 카드 | 골라져 온 단품 하나 |
| 묶음 카드 | 골라져 온 단품이 든 묶음만 그린다. 정통사주 · 웹툰궁합에서 왔으면 추천 묶음과 전체 묶음, 정통궁합에서 왔으면 전체 묶음만 |
| 묶음에 든 것 가운데 이미 가진 것이 있다 | 그 묶음 카드를 그리지 않는다 |
| 묶음에 든 것 가운데 그 두 사람에게 그려지지 않는 것이 있다 | 그 묶음 카드를 그리지 않는다. 성별이 같은 두 사람은 웹툰궁합이 그려지지 않는다(app/ssom.js:21, 29, 242) |
| 묶음에 든 상품의 열쇠가 꾸러미에 없다(그 사람을 아직 안 골랐다) | 그 카드는 고를 수 없고, 그 사람을 고르러 가는 길만 보인다 |
| 고른 상품이 이미 열려 있다 | 결제 단추 대신 「이미 열려 있어요 → 바로 보러 가기」 |
| 꾸러미 없이 바로 왔다(푸터 「상담 신청」 · 북마크) | 진열만 보인다. 카드를 누르면 그 탭으로 간다. 결제 단추는 없다 |

- 카드마다 「든 것」을 적는다. 단품도 적는다(정통사주 = 웹툰과 근거 장, 웹툰궁합 = 단계 일곱 이야기, 정통궁합 = 근거 장).
- 결제 단추는 로그인 · 결제 이력 수신 · 상품 조회가 다 끝난 뒤에만 켠다. 그 전에는 눌리지 않는다. 로그인 전에는 단추 자리에 로그인으로 가는 단추가 선다.
- 추천 묶음의 대상 줄은 두 줄이다: 정통사주는 누구 것, 웹툰궁합은 어느 두 사람 것. 전체 묶음은 세 줄이다.
- 묶음의 정통사주는 「나」(지금 고른 명식) 것이다.

**금액 상자 계산(전부 상품표 값으로)**
- 단품을 고르면: 상품값 = 최종 결제금액. 할인 줄은 그리지 않는다.
- 묶음을 고르면: 상품값 = 묶음에 든 단품 값의 합. 묶음 할인 = 그 합 − 묶음 값. 최종 결제금액 = 묶음 값.
- 묶음 값이 합보다 작지 않으면 할인 줄을 그리지 않는다.
- 견주는 값은 같은 화면에서 지금 파는 단품 값뿐이다.

**토스 연동(공식 문서에서 확인한 것만 · 09-29)**
- 주문서형 차례: `widgets({ customerKey })` → `setAmount` → `renderPaymentMethods({ selector })` → `renderAgreement({ selector })` → `requestPayment({ orderId, orderName, successUrl, failUrl })`. 휴대폰 번호 · 메일 · 이름은 선택 값이다.
- `setAmount` 는 결제수단을 그리기 전에 부른다. 카드를 바꿔 금액이 달라지면 `setAmount` 를 다시 부른다.
- 결제 상태 값: `WAITING_FOR_DEPOSIT` 은 가상계좌에 아직 입금하지 않은 상태, `DONE` 은 결제가 승인된 상태다.
- 출처: docs.tosspayments.com/guides/v2/payment-widget/integration · docs.tosspayments.com/reference (Payment 객체 status)
- 지금 키는 `test_gck_`(주문서형 · 결제창형 연동 키)라 그대로 쓴다. 지금 코드는 같은 키로 결제창형(`renderPaymentWindow`)을 쓰고 있다(app/pay.js:141-184).
- 다른 종류 키(ck)가 들어오면 ② 칸을 접고 지금의 결제창 길(`buy`)로 물러난다.
- 주문은 ⑤ 단추를 누른 뒤에 연다(`order_open`). 서버가 돌려준 금액으로 `setAmount` 를 한 번 더 맞추고 결제를 청한다.
- 금액 대조(api/pay.js:145-168)는 그대로다. 출산택일 신청 페이지도 지금 흐름 그대로 둔다.

**승인 응답의 상태를 본다**
- 지금 서버는 토스 승인이 HTTP 성공이면 곧바로 결제완료로 적는다(api/pay.js:170-229). `DONE` 확인은 조회로 물러난 갈래에만 있다(api/pay.js:198).
- 바꾼 뒤: 승인 응답의 `status` 가 `DONE` 일 때만 `order_paid` 를 부른다. 아니면 결제 조회로 한 번 더 묻고, 그래도 `DONE` 이 아니면 주문을 `open` 으로 둔 채 「입금이 확인되면 열린다」고 답한다(글은 작가).
- 결제 확인 화면에 「다시 확인」을 둔다. 누르면 서버가 토스 조회로 다시 묻고, `DONE` 이면 그때 결제완료로 적는다.
- 입금 알림(웹훅)은 이번에 만들지 않는다. 입금 대기로 답하는 결제수단이 켜져 있으면 손님이 입금 뒤 「다시 확인」을 눌러야 열린다. 어떤 수단이 켜져 있는지는 확인하지 못했다(사장님 할 일 4).

**상품이 골라진 채로 오는 길**
- 잠금 상자 · 잠긴 표지의 단추를 누르면 앱이 꾸러미를 남기고 `pay.html?p=코드` 로 간다. 주소에는 상품 코드만 싣는다.
- 꾸러미: `localStorage` 의 `chaeksa.payPick`, 30분 지나면 버린다. 장면 보기의 잠긴 표지가 뜰 때 시각을 새로 적는다(읽는 동안 끊기지 않게).

```
{ p: 'ssom',                                   골라진 상품
  keys: { jeongtong: '…', chongnon: '…', ssom: '…' },   앱이 그 자리에서 만든 열쇠(만들 수 있는 것만)
  who:  { me:  { 이름, 관계, 날 },              대상 줄에 쓴다. 이 기기 화면에만 보인다
          you: { 이름, 관계, 날 } },            주소 · 서버로는 안 간다
  can:  { ssom: true },                        이 두 사람에게 웹툰궁합이 그려지나
  stop: { 곳: '근거' | '글' | '장면',           결제 뒤 돌아갈 자리
          첫잠금: 번호, 단계: '…' },
  back: '#ssom',                               결제 뒤 돌아갈 탭
  at: 시각 }
```

- 열쇠는 앱이 잠금 상자를 그린 그 자리에서 만든다. 잠긴 것을 본 그 사람 · 그 쌍이 그대로 열린다.
- 열쇠 없이 결제되는 길을 남기지 않는다(지금 pay.html:181-186 이 옛 장에 하던 방식).
- 로그인은 결제 화면 안에서 받는다. 떠나기 전에 `chaeksa.return` 에 `/pay.html` 을 남기면 앱 시작부가 돌려보낸다(app/app.js:2886-2899, 출산택일 신청 페이지가 쓰는 길). 돌아올 때 주소의 `?p=` 는 떨어진다. 골라진 상품은 꾸러미의 `p` 로 되살린다.
- 로그인하고 돌아오면 결제 이력을 받아 카드를 다시 그린다. 가진 상품은 「이미 열려 있어요」로 바뀐다.
- 이 기기에서 시작하지 않은 로그인이면 결제 전에 어느 계정인지 묻는 지금 물음(app/pay.html:213-223)은 그대로 둔다.

**묶음을 DB 에 넣는 법**

| 넣는 곳 | 무엇 | 까닭 |
|---|---|---|
| `products.opens text[]`(새 열) | 그 상품이 여는 단품 코드들. 단품 셋은 자기 코드 하나. 출산택일은 비움 | 묶음 구성도 값처럼 표 한 곳에만 둔다. 비어 있으면 열쇠를 검사하지 않는 상품이다 |
| `orders.opens text[]`(새 열) | 주문을 열 때 `products.opens` 를 베껴 둠 | 주문 당시의 이름 · 값을 주문에 적어 두는 것과 같은 이치. 묶음을 나중에 내려도 산 사람 것은 그대로 열린다 |
| `orders.note` | 여는 상품마다 열쇠 한 조각, `\|` 로 잇는다 | 예: `jeongtong:조각\|ssom:조각`. 500자 안(api/pay.js:118) |
| `orders.first_view_at`(새 열) | 첫 열람 시각. 그 주문으로 열린 탭을 앱이 처음 그린 때다. 주문 하나에 시각 하나이고, 한 번 적으면 바꾸지 않는다. 묶음은 든 것 가운데 하나라도 그린 때 | 약관 9절 「열람이 시작되면」의 근거. 묶음을 통째로만 취소하는 규칙과 맞다 |

- 묶음 코드: 추천 묶음 `duo` = 정통사주(나) + 웹툰궁합(그 두 사람), 전체 묶음 `trio` = 정통사주(나) + 정통궁합 + 웹툰궁합. 주문번호에서 코드를 읽는 식이 소문자 영문만 받는다(app/pay.js:362 · app/pay-done.html:158).
- 열리는 규칙: 결제된 주문 가운데 ① `opens` 에 그 상품 코드가 있고 ② `note` 를 `|` 로 갈랐을 때 그 코드의 조각이 열쇠와 글자까지 같은 주문이 하나라도 있으면 연다. 코드마다 첫 조각만 인정한다.
- 묶음으로 열리는 것은 그 주문에 적힌 사람 · 쌍 것뿐이다. 다른 사람 · 다른 두 사람은 따로 산다.
- 첫 열람은 한 가지로만 센다: 산 주문 때문에 「열림」이 된 탭(정통사주 · 정통궁합 · 웹툰궁합)을 앱이 처음 그린 때다. 약관 9절 · 결제 화면의 동의 · DB 열 · 함수가 모두 이 말을 쓴다.
- 결제 뒤 「바로 보러 가기」로 돌아오면 탭이 방금 열린 첫 회 · 장을 펼쳐 보인다. 그때가 곧 첫 열람이다.
- 장면 보기는 탭을 거쳐서만 들어가므로 따로 적지 않는다. 유효 잠금이 꺼져 있거나 super 계정이라 열린 화면은 주문이 없어 적지 않는다.

**주문을 열 때 서버가 검사하는 것(`order_open`)**

| 검사 | 어긋나면 |
|---|---|
| 조각 수 = `opens` 수 | `bad_key` |
| `opens` 의 코드마다 조각이 꼭 하나 | `no_key`(빠짐) · `bad_key`(겹침) |
| `opens` 밖의 코드가 든 조각 | `bad_key` |
| 조각의 꼴 `^[a-z]+:[a-z0-9]+$` | `bad_key` |
| 같은 계정에 같은 코드 · 같은 조각의 결제된 주문이 있다(묶음은 든 것 가운데 하나라도) | `already` |

- 돈을 내고 아무것도 안 열리는 일, 조각을 여러 개 끼워 한 번 결제로 여러 쌍을 여는 일, 같은 것을 두 번 내는 일을 서버에서 막는다.
- 묶음에서 「하나라도 겹치면 거절」로 둔 까닭: 화면이 그 묶음 카드를 그리지 않는 규칙과 같게 맞췄다. 가진 것에 값을 또 내게 하지 않는다.

**결제 뒤 돌아오는 길**
1. 토스 → `pay-done.html` 이 승인을 청한다.
2. 결제 확인 화면은 열린 것마다 한 줄씩 「누구 것 · 바로 보러 가기」를 보인다. 묶음이면 둘 · 셋이다.
3. 갈 곳은 꾸러미의 `back` · `stop` 으로, 없으면 코드로 정한다: jeongtong → `./#jeongtong`, chongnon → `./#chongnon`, ssom → `./#ssom`.
4. `?go=` 는 쓰지 않는다. 프로필이 있는 사람은 홈에 떨어진다(읽기 단계 실측, app/app.js:2684). `#탭` 은 열린다(app/app.js:487-503).
5. 탭은 돌아오면 방금 열린 첫 회 · 장을 펼쳐 그 자리로 내려간다. 장면 보기에서 막혔던 사람은 첫 잠금이던 회의 표지부터 열린다. 이때가 첫 열람이다. 앱이 그 주문에 시각을 적는다(한 번만).
6. 앱이 부팅할 때 주소 해시가 살아 있는 탭이면 복귀대기를 켠다. 지금은 서버 병합에서 바뀐 것이 있으면 몇 초 뒤 홈으로 되돌아가고(app/app.js:2811-2819 → 518), 복귀대기는 로그인 복귀 길에서만 켜진다(app/app.js:2897).
7. 꾸러미는 이 길을 다 만든 뒤에 지운다.

**결제 실패 · 취소 화면(app/pay-fail.html)**
- 지금은 「책사로 돌아가기」(홈)뿐이고, 이 기기에 출산택일 초안이 있으면 어떤 결제가 실패해도 「신청서로 돌아가 다시 결제하기」를 앞세운다(app/pay-fail.html:31-32, 57-62).

**환불한 주문**
- 환불은 지금 토스 상점 관리자에서 손으로 한다(docs/17_결제.md:120). 주문 상태를 `canceled` 로 바꾸는 함수는 저장소에 없다. 상태 값 자체는 표에 있다(server/schema-8.sql:56).

### 2. 자르는 곳

| 상품 | 무료 | 잠금 | 누가 정했나 |
|---|---|---|---|
| 정통사주 · 웹툰 20회 | 1~4회 | 5~20회 | 메인 추론(검수 대상) · 아래 가 |
| 정통사주 · 근거 장 | 1~4장 | 5~10장 · 12장 | 메인 추론(검수 대상) · 아래 나 |
| 정통궁합 | 1~4장 | 5~10장 · 12장 | 메인 추론(검수 대상) · 아래 다 |
| 웹툰궁합 | 3초 결과 카드 + 「두 사람 이야기」 1~4회 + 단계마다 한 회 | 단계마다 나머지 회 | 내 안(검수 대상) · 아래 라 |

늘 무료로 두는 것: 공유 카드 둘(정통사주 한 줄 카드 · 웹툰궁합 3초 결과 카드), 홈의 내 원국, 3장 안의 설명서, 「이번 주엔 무엇이 바뀌나」(값 없음 · 이번 대상 아님).

상수는 한 곳에 둔다. 숫자 하나로 바꾼다.

```
무료   = { jeongtong: { 회: 4, 장: 4 }, chongnon: { 장: 4 },
           ssom: { 둘: 4, 단계: 1, 고른회: ['시작전'] } }     고른회 = 첫 회가 아니라 손님이 고른 한 회를 여는 단계
안 셈  = { jeongtong: [11, 13], chongnon: [11, 13] }      파는 장으로 세지 않는 장
```

- `고른회` 에 든 단계는 앞에서부터 세지 않고 손님이 고른 회를 연다. 지금은 「시작 전」 하나다(단계 키 `시작전` — app/ssom-dangye.js:11). 여는 회 수는 `단계` 값 그대로다. `단계` 를 0 으로 바꾸면 고른 회도 열지 않는다.

**가. 정통사주 웹툰 — 1~4회**
- 1 · 2회(태어난 날 묶음)를 다 보고, 3회(회사로 치면 어느 자리)와 4회(잘하는 것 · 걸려 넘어지는 것)까지 본다.
- 공유 카드의 한 줄이 3회 답에 있다. 카드를 받고 온 사람이 무료 안에서 확인한다.
- 첫 잠금이 5회 「나를 거기 앉혀 준 건 누구일까요?」다. 같은 묶음 안에서 끊겨 다음 회가 궁금한 자리다.
- 다른 안: 5회까지 열면 묶음 경계와 맞고, 첫 잠금이 되는 6회 답에 처음으로 실제 연도가 나온다. 다만 다섯은 「서너 가지」를 넘는다. 그래서 4로 두었다.

**나. 정통사주 근거 장 — 1~4장**
- 1~3장이 3대 고전(적천수 · 궁통보감 · 자평진전), 4장이 자리마다 내 힘(십이운성)이다.
- 첫 잠금이 5장 신살(역마 · 도화 · 화개)이다. 제목만 봐도 궁금한 장이다.
- 다른 안: 3장까지. 「3대 고전」 덩어리와 맞고 3장이 「당신은 …사람이에요」와 설명서로 끝난다. 4장은 명식에 따라 어두운 풀이로 끝날 때가 있어, 바로 뒤에 결제 상자가 오면 거슬릴 수 있다.
- 사장님이 맡기셔서 메인 추론대로 4로 두었다(검수 대상). 3은 검수에서 고르실 수 있게 적어 둔다.

**다. 정통궁합 — 1~4장**
- 5장 본문이 스스로 「3 · 4장이 칸이고 이 장이 글자예요」라고 말한다. 1~4장이 한 덩어리다.
- 4장 첫 줄이 「각자 어떤 사람에게 끌리나」의 답이라 무료의 끝으로 알맞다.
- 글자 수(09-29 개발 서버에서 다시 쟀다 · 만든 예 두 사람 1990-5-15 여 · 1992-11-3 남, 둘 다 낮 12시 · 공백과 장 제목 · 부제는 빼고 본문만): 앞 4장 1,380자, 파는 일곱 장(5~10장 · 12장) 5,408자. 11 · 13장은 세지 않았다. 11장의 한 줄을 12장 머리로 옮기기 전 화면이다. 정통궁합 탭에 같은 두 사람을 넣으면 같은 화면이 나온다.

**라. 웹툰궁합 — 「두 사람 이야기」 4회 + 단계마다 한 회**
- 「두 사람 이야기」 4회는 설명하는 글이다. 사건과 대사가 오가는 본편은 단계 이야기다. 본편을 한 회도 못 보고 19,900원을 내게 하지 않는다.
- 어느 단계의 손님이든 자기 단계 첫 회를 상황 → 서로의 언행 → 근거 한 벌로 보고 잠금을 만난다.
- 회 경계에서 자르므로 회 안의 이야기는 끊기지 않는다.
- 잠긴 회는 질문 제목과 컷이 보여, 무엇을 사는지 안다.
- 단계 회 수는 6 · 6 · 5 · 4 · 4 · 3 · 3 이다(읽기 단계 확인).

| 무엇 | 회 수 |
|---|---|
| 한 손님이 실제로 보는 무료 | 3초 결과 카드 + 「두 사람 이야기」 4회 + 자기 단계 1회 |
| 단계 일곱을 다 눌러 봤을 때의 무료 | 「두 사람 이야기」 4회 + 단계 7회 = 11회 |
| 잠금 | 단계마다 나머지 회(수는 화면이 뼈대 길이에서 계산) |

- 「서너 가지」보다 많다. 말씀 그대로의 안은 상수 하나(단계: 1 → 0)로 바뀐다. 그러면 무료는 3초 결과 카드 + 「두 사람 이야기」 4회뿐이고 단계 카드를 누르면 바로 잠금이다.
- 「시작 전」은 만나는 곳 여섯이 나란한 가정이다. 첫 회(소개팅)를 고정으로 열면 다른 곳에서 만난 사람은 남의 장면을 맛보기로 본다. 그래서 여섯 가운데 손님이 고른 한 곳을 연다. 무료 회 수는 그대로 하나다. 고른 곳은 이 기기에 그 두 사람 것으로 기억하고 바꾸지 않는다. 나머지 다섯은 잠긴 제목으로 보인다. 상수의 `고른회` 가 이 규칙이다.
- 회 안에서 자르는 안(장면은 보이고 근거만 잠금)은 쓰지 않는다. 회의 뼈대가 깨지고 글 보기와 장면 보기가 달라진다.

**네 축으로 본 무료와 유료(웹툰궁합)**
- 3초 결과 카드 = 세속적인 상식과 언어로 말하기(세계실단).
- 「두 사람 이야기」 = 듣는 사람에 따라 다르게 말하기(각각위인실단).
- 단계 이야기 = 특정 상황에 맞는 해결책을 말하기(대치실단).
- 회 끝 「사주에서 본 근거」 = 진리를 대놓고 말하기(제일의실단).
- 앞의 둘은 무료로 주고, 「지금 내 단계에서 어떻게 되나」를 판다.

- 잠금 상자가 말하는 수는 그 사람 · 그 두 사람에게 본문이 실제로 그려지는 회 · 장만 센다. 자르는 상수와 뼈대 길이, 「안 셈」 목록, 그려지지 않는 장(모듈 없음 · 시간이나 성별을 몰라 못 그리는 장)에서 계산한다. 손으로 적지 않는다.
- 11장을 가리키는 화면 글은 열한 곳이다. 열 곳은 12장을 가리키게 고친다. 나머지 한 곳은 정통궁합 12장 자기 머리라(app/gunghap-gwanjeom.js:685 — app/gunghap-chongnon.js:101 이 그 머리를 그대로 그린다) 11장을 가리키는 말을 걷는다(글은 작가 · 자리는 하려던 말 표).

### 3. 열쇠

**무엇을 note 로 쓰나**

| 상품 | 열쇠 |
|---|---|
| 정통사주 | `jeongtong:` + 판 표시 + 그 사람 생년월일 날짜를 섞은 글자열 |
| 정통궁합 | `chongnon:` + 판 표시 + 두 사람 날짜를 차례 맞춰 이은 뒤 섞은 글자열 |
| 웹툰궁합 | `ssom:` + 판 표시 + 위와 같은 쌍 글자열 |

**산식(얼려 둔다 · 판 v1)**

```
날(p)      = 연-월-일      궁합입력()의 year · month · day 를 숫자로 바꾼 뒤 '-' 로 잇는다. 0 을 채우지 않는다(1992-4-21)
사람 바탕  = 날(a)
쌍 바탕    = [날(a), 날(b)] 를 글자 차례로 늘어놓고 '+' 로 잇는다
섞기(s)    = FNV-1a 32비트 둘을 이어 붙인다
             a = f(s, 0x811c9dc5)        f: 글자마다 h ^= 글자 코드, h = (h × 0x01000193) 을 32비트로
             b = f(s + '#', a)
             a · b 를 36진 소문자로, 앞을 0 으로 채워 7자씩 → 14자
열쇠       = 코드 + ':' + 'v1' + 섞기(바탕)
```

고정 값(만든 예 날짜다. 설계 단계에서 같은 산식을 파이썬으로 돌려 냈다. 시험 8 이 브라우저에서 같은 값이 나오는지 본다).

| 바탕 | 열쇠 |
|---|---|
| `2000-1-1` | `jeongtong:v11fzb1pf0qc018y` |
| `1990-5-15+1992-11-3` | `chongnon:v101pe81s020yqn4` |
| 위 두 사람의 자리를 바꿔 넣음 | 위와 같은 값 |

- 만드는 곳은 한 군데(`ChaeksaPay.열쇠`)다. 앱 · 결제 화면 · 시험이 같은 함수를 쓴다.
- 산식이나 바탕 꼴을 바꾸면 산 사람 전부가 다시 잠긴다. 바꿔야 하면 판 표시를 올리고, 옛 판 열쇠도 같이 맞춰 본다.
- **시각은 넣지 않는다.** 태어난 시간을 나중에 넣거나 고쳐도 산 것이 다시 잠기지 않는다. 읽기 단계 실측으로 시간이 있고 없음에 따라 내용이 달라지는 것은 확인했다. 그래도 산 사람 쪽에 너그럽게 간다.
- **성별 · 음양력 · 경도도 넣지 않는다.** 모름에서 고치거나 잘못 넣은 것을 바로잡는 일이 있다.
- **쌍은 두 사람을 다 넣고 차례를 맞춘다.** 「사람 바꾸기」로 나와 그 사람 자리를 바꿔 봐도 산 것이 열린다. 나를 다른 사람으로 바꾸면 다른 쌍이라 따로 산다.
- 옛 꼴(`코드:연-월-일-시-분`, 그 사람 것만 — app/app.js:968, 1203)은 새 상품에 쓰지 않는다.

**쓰지 않는 후보**

| 후보 | 안 쓰는 까닭 |
|---|---|
| 웹툰궁합의 z.키(일주 × 식상) | 한자가 섞여 있고, 그 사람 시각을 넣으면 달라지는 쌍이 있다(읽기 단계 표본 1,200 가운데 242). 나와 그 사람을 바꾸면 뒤집힌다 |
| 일주 번호 | 생일은 안 드러나지만 다른 사람이 60분의 1쯤 같은 열쇠가 된다. 「개별로 받아야지」(09-04)에 덜 맞는다 |
| 사람 id | 지웠다 다시 넣으면 새 id 라 산 것이 잠긴다 |
| 옛 꼴 그대로 | 그 사람 생년월일시가 주문 기록에 글자 그대로 남는다 |

**생일이 드러나지 않나**
- 주소(URL)에는 상품 코드만 실린다. 열쇠는 결제 요청 본문으로만 서버에 간다(app/pay.js:111).
- 토스에는 주문번호 · 상품 이름 · 금액만 간다. 열쇠는 안 간다(app/pay.js:131).
- 주문 기록(`orders.note`)에는 섞은 글자열만 남는다. 생년월일 글자는 남지 않는다.
- 결제 화면 대상 줄의 생년월일은 꾸러미(이 기기의 localStorage)에서 읽어 화면에만 보인다.
- 다만 섞은 글자열은 암호가 아니다. 날짜 가짓수가 적어, DB 를 손에 쥔 사람은 되짚을 수 있다. 맨눈으로 안 읽히게 하는 것까지다.
- 로그인한 사람의 등록 인물은 이미 서버에 보관된다(app/privacy.html:79). 열쇠 때문에 서버가 새로 알게 되는 것은 없다.
- 탈퇴하면 note 는 지워진다(server/migrate-25-order-retention.sql:27).
- 개인정보처리방침 결제 줄은 「상대의 생년월일시를 주문에 함께 적습니다」로 돼 있다(app/privacy.html:42). 새 열쇠와 첫 열람 시각에 맞게 고쳐야 한다(글은 작가).

**날짜를 고친 사람**
- 생년월일을 고치면 열쇠가 달라져 다시 잠긴다. 그래서 결제 전에 날짜를 확인하게 한다(결제 화면 대상 줄 · 잠금 상자).
- 그래도 생기면 사람 손으로 푼다: 주문번호를 받아 사장님이 그 주문의 note 를 새 열쇠로 고친다. 새 열쇠는 super 계정 화면에서 뽑는다.

**시험 결제로 생긴 주문**
- 지금 브라우저는 시험 결제와 운영 결제를 가리지 않는다(app/pay.js:343-350). `my_orders` 가 결제 모드를 내려주지 않기 때문이다(server/migrate-17-my-orders-note.sql:13-15).

| 주문의 결제 모드 | 열리나 |
|---|---|
| 운영(live) | 결제 이력이 오면 바로 열린다. 상품 조회를 기다리지 않고, 상품 조회가 실패해도 열린다 |
| 시험(test) | 지금 키가 `test_` 로 시작하는 것이 확인됐을 때만 열린다. 운영 키로 확인되면 열리지 않는다(산 주문이 없는 것으로 친다). 키 종류를 아직 모르면 열지 않고 상태는 「기다림」, 상품 조회가 실패했으면 「확인 못 함」이다 |
| 비어 있음 | 운영 주문과 같게 연다. 모드 적기가 두 번 실패하면 운영 결제도 모드가 빈다(api/pay.js:236-238). 돈 낸 사람을 잠그지 않는다 |

- 모드가 빈 주문은 사장님이 손으로 채운다. `my_orders` 가 결제 시각을 같이 내려주고, 채우는 SQL 은 docs/17 에 둔다(수9).
- `paidForKey` 는 동기 함수이고, 키 종류는 상품 조회에 실려 늦게 온다(app/pay.js:121, 141). 결제 이력이 왔으면 운영 주문 · 모드 빈 주문은 바로 돌려주고, 시험 주문은 키가 `test_` 로 확인된 뒤에만 돌려준다.
- 「받았나」(`paidReady`)는 결제 이력과 상품 조회를 둘 다 받았을 때 참이다. 「산 주문이 없다」를 믿어도 되는 때를 말한다. `paidForKey` 가 주문을 돌려주면 `paidReady` 와 상관없이 「열림」이다.
- 상태를 정하는 차례는 4절에 있다.

## 기대되는 결과물

### 4. 잠금 화면의 모양

**유효 잠금**

```
유효 잠금 = CHAEKSA_LOCK 이 1 이다  또는  이 기기에 미리 보기 표시가 있다
```

| 때 | 결과 |
|---|---|
| 주소에 `?lock=1` | 이 기기에 미리 보기 표시를 남긴다 |
| 주소에 `?lock=0` | 미리 보기 표시만 지운다. 스위치가 켜져 있으면 그대로 잠긴다 |
| 스위치가 켜졌는데 장면 보기로 온 꾸러미에 잠금 정보가 없다 | 잠김(무료 회까지만) |
| 스위치가 켜졌는데 `ChaeksaLock` 이 실리지 않았다 | 잠김(무료 회 · 장까지만) |
| 스위치가 꺼졌고 미리 보기 표시도 없다 | 지금 화면 그대로 |

- 그리는 파일(jeongtong.js · gunghap-chongnon.js · ssom.js)과 장면 보기(ssom-vn.html) · 결제 화면(pay.html)은 `config.js` 의 스위치를 직접 읽는다. 잠금 모듈이 빠져도 스위치가 이긴다.
- 미리 보기는 가리는 쪽으로만 바뀐다. 스위치를 켜기 전에 사장님이 라이브에서 잠긴 화면과 결제 흐름을 시험 키로 검수하는 길이다.

**상태 넷**

| 상태 | 언제 | 화면 |
|---|---|---|
| 열림 | 유효 잠금 꺼짐 · super 계정 · 산 사람(그 열쇠로 열리는 주문이 있다) | 기준 판과 글자까지 같다. 잠금 글자 0. 산 사람의 정통사주 장면 보기에 해설 줄이 더 있는 것만 다르다 |
| 잠김 | 유효 잠금 켜짐 + 산 주문이 없다(로그인 안 함 포함) + 상품 조회를 받아 값이 있다 | 무료 회 · 장은 그대로. 잠긴 것은 제목만. 잠금 상자 하나 |
| 기다림 | 유효 잠금 켜짐 + 아직 정할 수 없다: 결제 이력을 못 받았다 · 시험 주문뿐인데 키 종류를 모른다 · 산 주문이 없는데 상품 조회(값)를 못 받았다 | 무료 회 · 장만 그린다. 잠금 글자도 잠긴 본문도 없다. 받으면 다시 그린다 |
| 확인 못 함 | 기다림이 한도를 넘었거나 기다리던 조회가 실패했다 | 잠금 상자 자리에 값 · 잠금 글자 없이 「아직 확인하지 못했어요 · 다시 확인」. 누르면 다시 받는다 |

**상태를 정하는 차례**

위에서부터 본다. 먼저 맞는 줄에서 멈춘다.

| 차례 | 물음 | 상태 |
|---|---|---|
| ① | 유효 잠금이 꺼져 있다 · super 계정이다 | 열림 |
| ② | 로그인했는데 결제 이력을 아직 못 받았다 | 기다림. 한도를 넘거나 이력 조회가 실패하면 확인 못 함 |
| ③ | 결제 이력에 그 열쇠의 운영 주문이나 모드 빈 주문이 있다 | 열림. 상품 조회를 보지 않는다 |
| ④ | 그 열쇠의 주문이 시험 주문뿐이다 | 키가 `test_` 로 확인됐으면 열림 · 운영 키로 확인됐으면 ⑤ 로 간다 · 키 종류를 아직 모르면 기다림 · 상품 조회가 실패했으면 확인 못 함 |
| ⑤ | 산 주문이 없다(로그인 안 함 · 환불한 주문뿐인 때 포함) | 상품 조회를 받았으면 잠김 · 아직이면 기다림 · 실패했으면 확인 못 함 |

- 값은 상품 조회에서 온다. 상품 조회를 못 받은 동안에는 잠금 상자를 그릴 수 없다. 그래서 그동안은 「잠김」이 되지 않는다.
- 운영 결제를 한 사람은 상품 조회가 실패해도 「열림」이다. 상품 조회는 시험 주문을 가릴 때와 값을 그릴 때만 본다.
- 「기다림」을 두는 까닭: 결제 이력은 늦게 온다(app/pay.js:332-350). 그 사이에 잠금 상자를 그리면 산 사람에게 잠금이 번쩍 보인다.
- 「확인 못 함」을 두는 까닭: 조회가 실패하면 캐시 없이 null 이 온다(app/pay.js:343-347). 그대로 두면 산 사람은 산 것을 못 보고, 안 산 사람은 살 길이 없다.
- 기다림 한도는 상수 하나다(내 안 5초 · 검수 대상).

**흐름**

```
무료 회 · 장(본문 그대로)
→ 잠긴 회 · 장: 제목만(근거 장은 제목 + 부제, 웹툰은 질문 제목 + 컷). 본문은 짓지 않는다
→ 잠금 상자(글 보기 · 근거 장) 또는 잠긴 표지(장면 보기)
→ 단추 → 결제 화면(그 상품이 골라진 채)
→ 결제수단 · 금액 · 동의 · 「○○원 결제하기」
→ 결제 확인 화면 → 열린 것마다 「바로 보러 가기」 → 멈췄던 자리
→ 전부 열림. 잠금 글자 0
```

**잠금 상자**

상자 함수가 받는 값은 이것으로 못 박는다.

```
ChaeksaLock.상자(code, { 잠긴묶음들, 수, 대상, 가진것, 모르는것 })
  잠긴묶음들   묶음 이름으로 접은 서너 줄(정통사주 웹툰은 뼈대의 묶음 이름, 웹툰궁합은 단계 이름)
  수           한 번 결제로 열리는 회 · 장의 수(계산한 값)
  대상         누구 것 · 어느 두 사람 것(이름, 없으면 관계 + 생년월일 날짜)
  가진것       같은 사람 · 같은 쌍으로 이미 가진 다른 상품
  모르는것     태어난 시간 · 성별 가운데 모르는 것
```

| 상품 | 상자의 자리 | 수 |
|---|---|---|
| 정통사주 | 근거 4장 바로 뒤 하나 | 웹툰 남은 회 + 근거 남은 장(두 화면을 같이 센다) |
| 정통궁합 | 4장 바로 뒤 하나 | 남은 장 |
| 웹툰궁합 · 단계 화면 | 그 단계의 무료 회 바로 뒤 하나 | 단계 일곱 전부의 남은 회 |
| 웹툰궁합 · 「두 사람 이야기」 화면 | 잠금 상자를 두지 않는다(0). 아래 다리 하나 | — |

- 화면마다 하나만 둔다. 잠긴 장마다 되풀이하지 않는다.
- 목차에서 잠긴 장을 누르면 잠금 상자로 내려간다.
- 값은 상품표에서 받아 끼운다. 상자 코드에 숫자를 적지 않는다.
- [필수] 동의 칸은 결제 화면에 있다. 상자에는 환불 규정 한 줄과 약관 링크만 둔다. 동의를 두 번 받지 않는다.
- 정통사주 근거 장은 「근거 보기」 접힘 안에 있다(app/index.html:250). 상자로 내려갈 때 접혀 있으면 먼저 편다.
- 로그인 안 한 사람의 상자에는 「이미 결제하셨다면 로그인」 길을 둔다. 로그인만으로 열린다.
- 모르는 것이 있을 때만 「시간 · 성별을 넣으면 더 보인다」 줄과 그 사람 정보 고치기로 가는 길이 보인다. 시각 · 성별은 열쇠에 안 들어가, 결제 뒤에 고쳐도 산 것이 잠기지 않는다.
- 깔때기 사건 이름은 지금 것을 그대로 쓴다: 잠금 상자가 보임 = `sheet`, 결제 화면의 결제 단추 누름 = `pay`(server/migrate-30-funnel.sql:3-4). 새 이름을 만들지 않는다.

**「두 사람 이야기」 끝의 다리**
- 「두 사람 이야기」 4회는 전부 무료라 그 화면에는 잠긴 회가 없다. 지금 장면 보기는 4회 끝에서 「두 분의 이야기는 여기까지예요」로 닫고 선택지가 처음부터 다시 · 목차 · 글로 보기뿐이다(app/ssom-vn.html:132).
- 글 보기는 4회 뒤에, 장면 보기는 끝 선택지에 단계 이야기로 넘어가는 길을 둔다.
- 「두 사람 이야기」 화면에는 단계 회와 잠금 상자를 아예 짓지 않는다. 지금은 썸 여섯 회를 문자열로 다 지은 뒤 화면에서 덜어 낸다(app/ssom.js:159-164, 186-187).

**장면 보기(app/ssom-vn.html)**
- 장면 보기는 로그인 · 결제 모듈을 읽지 않는다(app/ssom-vn.html:65-67). 새로 싣지 않는다. `config.js` 는 이미 싣고 있어 스위치는 직접 읽는다.
- 앱이 장면 보기로 넘길 때 꾸러미에 잠금 정보를 같이 넣는다: 어느 상품인지 · 상태 · 무료 회 수 · 값(상품표에서 받은 값) · 잠긴 회 수 · 대상 · 돌아갈 탭.
- 앱은 넘기기 전에 결제 꾸러미(`chaeksa.payPick`)를 미리 써 둔다. 잠긴 표지의 단추는 결제 화면으로 곧장 간다(`pay.html?p=코드`).
- 잠긴 표지는 잠금 상자와 같은 내용을 보인다: 값 · 열리는 범위 · 누구 것.
- 「기다림」일 때 시작 단추를 누르면 결제 이력을 받은 뒤에 넘어간다. 「확인 못 함」이면 무료 회까지만 넘기고, 잠긴 표지에는 값 · 결제 단추 대신 「돌아가서 다시 확인」을 보인다.
- 대본이 잠긴 회에 표시를 달고 줄은 짓지 않는다.
- 회 넘김은 표지 한 곳을 거친다(다음 단추 · 목차 · 처음부터 다시 — app/ssom-vn.html:99-103, 130-141). 잠긴 회의 표지를 거기 하나만 두면 세 길이 다 막힌다.
- 「시작 전」은 손님이 고른 회부터 연다.
- 산 사람의 정통사주 대본에는 회마다 해설 줄을 넣는다(조립 결과에 이미 있는 줄). 단서는 넣지 않는다 — 09-25 결정 그대로.
- 견본(넘겨받은 값 없이 바로 연 경우)도 무료 범위까지만 보인다.
- 넘길 때 어느 모드인지 적고 반대쪽 값을 지운다. 지금은 정통사주 웹툰을 본 탭에서 웹툰궁합 장면 보기를 누르면 정통사주가 열린다(app/ssom-vn.html:76, 87).

### 5. 고칠 곳 — 담당별 작업 목록

서로 부를 이름을 먼저 못 박는다. 이 이름에 맞춰 두 담당이 나란히 일한다.

```
ChaeksaPay.열쇠(code, a, b)          열쇠 글자열. b 가 있으면 쌍
ChaeksaPay.paidForKey(code, key)     산 주문 또는 null (부르는 꼴은 지금 그대로)
ChaeksaPay.paidReady()               결제 이력과 상품 조회를 둘 다 받았나(「산 주문이 없다」를 믿어도 되는 때)
ChaeksaPay.paidReload()              결제 이력을 다시 받는다
ChaeksaPay.결제가기(꾸러미)           꾸러미를 남기고 결제 화면으로
ChaeksaPay.열람적기(주문)             첫 열람(그 주문으로 열린 탭을 처음 그린 때) 시각을 주문에 적는다(한 번만)
ChaeksaLock.무료 · ChaeksaLock.안셈   자르는 상수 · 파는 장으로 세지 않는 장
ChaeksaLock.유효()                   유효 잠금인가
ChaeksaLock.상태(code, key)          '열림' · '잠김' · '기다림' · '확인못함'
ChaeksaLock.수(code, 입력)            한 번 결제로 열리는 회 · 장의 수
ChaeksaLock.상자(code, 값)            잠금 상자 HTML(문구는 작가 표에서)
```

### 내가 정해 둔 것(검수 대상 — 틀린 곳만 짚어 주세요)

1. 자르는 곳: 정통사주 웹툰 1~4회 · 근거 1~4장, 정통궁합 1~4장. 사장님이 맡기셔서 메인 추론대로 두었다.
2. 웹툰궁합 무료 범위: 3초 결과 카드 + 「두 사람 이야기」 4회 + 단계마다 한 회. 한 손님이 실제로 보는 무료는 카드 + 4회 + 자기 단계 1회이고, 단계를 다 눌러 보면 11회다. 말씀 그대로의 안은 상수 하나(단계: 1 → 0)로 바뀐다.
3. 「시작 전」은 손님이 고른 만나는 곳 한 회를 무료로 연다. 자르는 상수에 `고른회` 로 적는다.
4. 11장(10년마다 바뀌는 운)은 두 상품 모두 파는 장으로 세지 않는다. 「지금 10년」 한 줄은 12장 머리로 옮기고 11장 제목은 목차에서 내린다. 장 번호는 다시 매기지 않는다. 09-27 「대운칸 삭제」 결정은 그대로다. 11장을 가리키는 화면 글 열한 곳을 같이 고친다.
