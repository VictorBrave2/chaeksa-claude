# 결제 (토스페이먼츠)

2026-08-28에 깔았다. **키만 넣으면 열린다** — 코드는 다 되어 있다.

## 우리 구조에서 왜 이렇게 되는가

토스 신청서의 「홈페이지 구축 방법」은 **직접 구축**이다.

```
호스팅        GitHub Pages (Actions 로 app/ 배포)     ← 정적. 서버가 없다
도메인        chaeksa.kr (카페24는 DNS 만)
서버          Vercel  chaeksa-claude.vercel.app       ← 여기에 붙였다
장부          Supabase  products · orders
```

**결제 승인은 서버가 비밀키로 불러야 한다.** 결제창이 닫혔다고 돈이 들어온 게 아니다.
GitHub Pages 는 이걸 못 하므로, 이미 있는 Vercel 함수 옆에 `api/pay.js` 를 얹었다.

## 돈 흐름

```
1  open      브라우저 → api/pay → Supabase order_open       금액을 DB 가 정한다
2  결제창     브라우저 → 토스 (orderId, amount)
3  confirm   브라우저 → api/pay → order_check 로 금액 대조
                              → 토스 /v1/payments/confirm
                              → order_paid
4  fail      브라우저 → api/pay → order_failed
```

착지 주소는 `chaeksa.kr/pay-done.html` · `chaeksa.kr/pay-fail.html`.

## 금액 위변조를 어디서 막는가

**한 자리에서만 막는다.** `api/pay.js` 의 `order_check` 대조다.

결제창에 보낸 `amount` 와 승인 요청의 `amount` 가 서로 같아도 아무 방어가 아니다 —
**둘 다 브라우저가 만든 값**이기 때문이다. 그래서 DB 의 `orders.amount` 와 맞춘다.
`orders.amount` 는 `order_open` 이 `products` 표에서 읽어 넣은 값이라 브라우저가 못 건드린다.

이 대조를 지우면 **100원 결제로 3만원짜리를 산다.**

같은 이유로 `orders` 에 insert/update RLS 정책을 안 열었다. anon key 는 공개값이라
누구나 Supabase 를 직접 부를 수 있고, 쓰기를 열면 그대로 무료 결제가 된다.
쓰기는 전부 `security definer` 함수로만 하고 함수 안에서 `auth.uid()` 로 임자를 본다.

## 가격은 한 곳에만 있다

`products` 표가 유일한 출처다. 화면은 `GET /api/pay` 로 **받아다 그린다** —
`app/pay.js` 에도 `app/pay.html` 에도 가격을 안 적었다.

두 벌이 있으면 반드시 어긋난다. 이 프로젝트에서 하루에 여섯 번 겪은 실패다
(서비스워커·검사 공식·가드·문서·forks vs gyeok·typecard vs gyeokguk).

가격을 바꿀 때는 SQL 로:

```sql
update public.products set amount = 35000 where code = 'taekil';
```

`schema-8.sql` 의 insert 는 `on conflict do nothing` 이라 다시 돌려도 안 덮어쓴다.

## 열 때 할 일

### 1. Supabase

SQL Editor 에 `server/schema-8.sql` 을 붙여넣고 실행.

### 2. Vercel 환경변수

```
TOSS_SECRET_KEY    필수. 여기 있어야 할 유일한 비밀. 절대 브라우저로 안 내려간다
TOSS_CLIENT_KEY    공개값. GET 응답으로 브라우저에 내려준다
```

**클라이언트 키를 `app/config.js` 에 안 둔 이유** — 비밀키와 짝이라서다.
따로 두면 한쪽만 바꿔 「인증 실패」가 나고, 원인을 찾는 데 반나절이 간다.

둘 중 하나라도 비면 `GET /api/pay` 가 `ready:false` 로 답하고,
`pay.html` 은 결제 버튼 대신 **카카오 안내**를 보여준다. 없는 버튼을 보여주지 않는다.

### 3. 토스 상점 설정

```
성공 URL   https://chaeksa.kr/pay-done.html
실패 URL   https://chaeksa.kr/pay-fail.html
서비스 URL https://chaeksa.kr
```

### 4. 확인

```
GET https://chaeksa-claude.vercel.app/api/pay
  → { ok:true, ready:true, clientKey:"...", products:[...] }
```

`ready:false` 면 환경변수, `products:[]` 면 schema-8 이 안 돌아간 것이다.

## 심사에 필요한 것

| | 상태 |
|---|---|
| 사업자등록증 | **사용자 쪽 진행 중** |
| 통신판매업 신고 | 사업자등록 뒤 |
| 정산 계좌 (사업자 명의) | |
| 가격이 정해진 상품 | ✅ `products` 4종 |
| 이용약관에 결제·환불 | ✅ terms.html 7~10절 |
| 청약철회 사전 고지 + 동의 | ✅ pay.html 체크박스 |
| 사업자정보 표기 | ⚠️ **terms.html 11절 — 등록번호가 나오면 채울 것** |
| 개인정보처리방침 | ✅ |

**「마음만큼」은 전자결제 심사를 못 통과한다.** 금액이 정해진 상품이 있어야 한다.
그래서 정가 상품을 열되, 「마음만큼」은 카카오 쪽에 그대로 남긴다.
`pay.html` 이 결제 준비 전에 보여주는 안내가 그것이다.

## 안 만든 것

- **웹훅** — 토스가 결제 상태 변화를 알려주는 통로. 지금은 승인이 브라우저를 거쳐
  일어나므로, 사용자가 승인 직전에 창을 닫으면 주문이 `open` 인 채 남는다.
  돈은 안 빠져나가니 손해는 없고, 거래가 늘면 그때 `api/pay-webhook.js` 를 붙인다.
- **취소·부분취소** — 환불은 지금 토스 대시보드에서 손으로 한다.
  건수가 적을 때는 이게 안전하다.
- **정기결제** — 월운 재구매가 붙으면 그때.
