## Design in brief

**How the server knows the product**
- Only from the database: orders.product → taekil_reports.product → taekil_take returns 'product'. The API passes it as opt.상품.
- Never from the intake or the request body. A verify intake could carry a range and still be judged correctly as verify, and a full-report intake must never be upgraded.
- A missing value (old DB function) means 'taekil'. Any other value fails (not_found).
- The product code 'taekil_check' (order id ck_taekil_check_…) is a suggestion. It needs to be agreed with the payment and SQL side.

**Verify mode (lib/taekil-report.js 만들기)**
- **검증읽기:** call the reader as now, then remove range and the full-report-only fields (time, weekend, first, hospital) from 막힘, 못읽음 and 줄. Set 기간 = min..max of the asked dates. Never use a range written in the intake.
- **Count and date checks:** 1~3 times allowed; otherwise input:have, input:have_count or input:have_past, and the report is blocked.
- **Engine dump:** use a new T.기간들 that builds the asked dates one by one, not min..max. No 31-day cap and no wasted days in between. It also attaches 대운 at each asked minute, because the dump has 대운 only for clean slots.
- **Picking:** new K.검증 = 고르기 with 덩어리 0 and weekend exclusion off, plus per-time 흠, family, hospital, the slot boundary, and one same-day better time.
- **Report sections:** greet · readback · verdict · check (items) · ask · method · clock · close · receipt. No steps, lenses, block, ziwei or summary.
- **AI:** only the 「궁금하다고 하신 것」 section, with a separate prompt. It receives no recommendation numbers and no lens rankings.
- **Checks:** the fixed list in 검사 depends on the product. The part, 대운, 원문 and 흠 checks also run on check items. The allowed ages include the asked-minute 대운. A new leak check blocks any full-report section from appearing in a verify report.

**Report shape and screen**
- The public renderer (app/taekil-report.js 칸(), lines 72-79) draws any section that has items, so a new 'check' section shows on screen without changes.
- Only 블로그칸 (line 140) and the page title belong to the screen side.

## Existing bug found (independent of this product; live DB not checked)
In the repo SQL, server/migrate-36-taekil-report.sql line 115 `_taekil_missing` always requires 'alldays'. Since 10-06 the private core no longer puts alldays in the report (lib/taekil-report.js line 667). If the live DB still runs this version:

## Deploy order (keeps paid content from leaking)
Private server (product-aware, leak check) → then SQL (_taekil_order accepts taekil_check). In the reverse order, a 50,000 verify order can get the full 99,000 report. It still needs an intake with a range, and it is released automatically only when auto-release is on.
