# 골드 케이스 — 「우리가 맞나」를 재는 자료

**2026-08-31 착수.** 지금까지 우리는 **한 번도 맞는지 재 본 적이 없다.**
`docs/13_검증앵커.md` 는 공식이 스스로와 어긋나지 않는지 보는 것이고,
`tools/enginecheck.js` 는 코드가 표대로 도는지 보는 것이다.
둘 다 **바깥의 진실과 대조하지 않는다.**

이 문서는 그 바깥을 들여오는 규칙이다.

---

## 하나 · 두 종류다. 섞지 마라

엔진의 주장은 **누가 반증할 수 있느냐**로 갈린다.

### 판정 골드 — 고전이 심판한다

원문에 명조와 판정이 함께 실린 것. 사람의 사생활이 없고, 시(時)까지 나와 있다.

| 우리 값 | 대조 대상 |
|---|---|
| `자평진전.격` | 원문이 무슨 격이라 했나 |
| `자평진전.판정` | 성격인가 패격인가 (성중유병·패중유성 포함) |
| `자평진전.상신` | 원문이 지목한 상신 |
| `억부.강약` | 해설의 신강·신약 |
| `궁통보감.필요한글자` | 조후용신 |

**이것이 먼저다.** 우리 엔진의 뼈대가 자평진전에서 나왔으니, 원문 명조로 어긋나면
그건 우리가 틀린 것이지 삶이 다른 게 아니다.

### 사건 골드 — 삶이 심판한다

실제 사람의 연표가 있어야 한다. 이것이 진짜 값어치지만 **동의 없이는 한 건도 안 받는다.**

| 우리 값 | 대조 대상 |
|---|---|
| `궁위한방.해` | 인연이 크게 움직인 해 (시작·굳음·틀어짐 무엇이든) |
| `열리는달_인연` · `열리는달_재물` | 실제 만남·수입이 있던 달 |
| `지킬해` · `샌해` | 큰 지출·손실이 있던 해 |
| `천직.유형` · `천직.일들` | 실제 직업 |
| `운로.최고구간` | 본인이 꼽는 가장 두터웠던 십 년 |
| `연애현재.판` · `재물현재.판` | 지금 상태 |

## 둘 · 동의 없이는 안 받는다

메모리 조문 그대로다 — **실제 사람의 상담을 동의 없이 자료로 쓰지 않는다.**
「익명이니까 괜찮다」는 틀리다. 댓글은 공개로 남아 대조 가능하고, 본인은 반드시 알아본다.

받을 수 있는 것:

1. **사장님 본인과, 명시적으로 동의한 지인** — 품질이 가장 높다. 시까지 정확하고 삶을 안다.
2. **동의를 받은 상담 고객** — 상담 때 「검증 자료로 써도 되겠습니까」를 따로 묻고,
   `동의` 칸에 날짜와 방법(카톡·댓글·메일)을 적는다.
3. **고전 명조** — 동의가 필요 없다. 사람이 아니라 문헌이다.

받지 않는 것:

- 동의 없는 댓글·문의
- 공개 인물 (생시가 없다. 12시진을 다 돌리면 판정이 흐려져 검증이 안 된다)
- 「어디서 본 사주」

**동의를 못 받았으면 그 케이스는 없는 것이다.** 아까워도 버린다.

## 셋 · 케이스 한 건의 모양

`tools/goldcases.json` 에 한 줄로 넣는다.

```json
{
  "id": "jp-001",
  "출처": "classic",
  "출전": "子平眞詮評註 卷三 論用神成敗救應",
  "입력": { "year":1875, "month":3, "day":12, "hour":14, "minute":0,
            "gender":"M", "place":"KR:서울" },
  "간지": "乙亥 己卯 甲子 辛未",
  "확정": { "격":"정관", "판정":"섰다", "상신":"인성", "강약":"신강" },
  "비고": "원문에 「官逢財印」으로 성격이라 적혔다"
}
```

- **`간지`를 반드시 적는다.** 우리가 뽑은 사주가 문헌과 같은지 먼저 맞춰야 한다.
  여기서 어긋나면 판정 비교는 의미가 없다 — 절기·진태양시부터 다시 본다.
- **`확정` 에는 아는 것만 적는다.** 모르는 항목은 넣지 않는다. 빈칸은 채점에서 빠진다.
- 사건 골드는 `확정` 대신 `연표` 를 쓴다:

```json
{
  "id": "life-001",
  "출처": "life",
  "동의": { "받은날":"2026-08-31", "방법":"카카오톡", "범위":"검증 자료로만" },
  "입력": { "year":1994, "month":6, "day":11, "hour":14, "minute":20,
            "gender":"F", "place":"KR:대구" },
  "연표": {
    "인연움직인해": [2018, 2023],
    "큰돈들어온해": [2021],
    "큰돈나간해":   [2019],
    "직업": "건설 · 설비",
    "가장두터웠던십년": "40대"
  },
  "비고": ""
}
```

## 넷 · 채점 규칙 — 후하게 매기지 마라

`tools/goldcheck.js` 가 돌린다. 브라우저 콘솔에서 `enginecheck` 와 같은 방식이다.

- **사주(간지)가 다르면 그 케이스는 통째로 실패다.** 판정은 채점하지 않는다.
- 판정 골드는 **정확 일치**만 맞음이다. 「비슷하다」는 없다.
- 사건 골드의 연도는 **±0년**이 맞음, **±1년**은 따로 센다.
  ±1을 맞음으로 세기 시작하면 무엇이든 맞는다.
- 열리는 달은 **그 달 하나**만 맞음이다.
- **맞은 것보다 틀린 것을 먼저 적는다.** 이 표는 자랑하려고 만드는 것이 아니다.

## 다섯 · 하지 않기로 한 것

- **적중률 숫자를 발행물에 쓰지 않는다.** 표본이 열 건인데 「70% 적중」이라 쓰면
  그건 재지 않은 것을 재었다고 말하는 것이다. 케이스가 충분히 쌓이고,
  그때 사장님이 결재하면 그때 연다.
- **골드 케이스로 공식을 맞추지 않는다(과적합).** 어긋난 것이 나오면
  먼저 `docs/13` 의 앵커로 기존 공식을 재판정하고, 조문으로 근거를 세운 뒤에 고친다.
  케이스 하나 때문에 조건을 덧대는 것이 이 집에서 제일 위험하다.
- 사람 이름을 저장소에 넣지 않는다. `id` 로만 부른다.
